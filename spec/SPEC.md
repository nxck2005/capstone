# Semantic Communication over Noisy Channels — Project Specification

**Status:** normative, hand-maintained. This file is the single source of truth for the project.
`DATASHEET.md`, `concerns/*.md` and `params.generated.yaml` are **generated from this file** — never edit those by hand.

**Keywords.** MUST, MUST NOT, SHOULD, SHOULD NOT and MAY are used in the RFC-2119 sense. A MUST that cannot be met is a spec change, not a quiet exception.

**Requirement IDs.** `SR` system · `BR` baseline · `ER` experiment · `DR` demo · `HR` hardware · `PR` programme deliverable · `OPT` optional/non-blocking · `FW` future work · `DEC` settled decision · `G` schedule gate · `AM` amendment. IDs are permanent: retire, never renumber. A retired ID is struck through in place and keeps its number reserved (§14).

**Amendments.** Any change to a requirement, decision, parameter or gate after this file first acquired that text is recorded as an `AM` entry in §17 stating what changed and why, and the amended item carries an `(AM-n)` back-reference. Nothing is edited silently. Rationale: this document is read by examiners and by external reviewers who did not see the previous version, and a spec that changes without a record cannot be distinguished from one that changed *because* of what the author later wanted it to say.

## 1. Purpose & thesis

Standard wireless practice compresses a source and separately protects the bits against noise, then rebuilds the file bit-for-bit at the receiver — an architecture optimised for pixel-perfect reconstruction. This project instead trains a neural **encoder** (sender) and **decoder** (receiver) end-to-end through a differentiable channel model, so that only what the downstream task needs survives the link.

The claim is structural, not a tuning result:

1. The **task-agnostic image-reconstruction baseline of record** — a standard source codec plus a standard channel code — has no representation of what the bits are *for*; its objective is fidelity, and task success is not expressible in it. This is a statement about *that* pipeline, not about digital systems in general: a digital transmitter could send quantised task features, logits or labels instead of an image. ER-9 builds exactly such a system as a control, so the thesis is tested rather than assumed.
2. Shannon's separation theorem makes compress-then-protect optimal only in the limit of infinitely long messages. Real edge/IoT links send **short** messages over **noisy** channels — a regime where separation is known to incur finite-blocklength and delay penalties, and where joint source-channel coding *may* therefore gain (Kostina & Verdú, arXiv:1209.1317). That is the hypothesis under test, not a theorem being applied.
3. The observable signature is **graceful degradation**: separated coding has a cliff below which the receiver gets nothing, while the learned system degrades continuously — blurrier, still task-correct.

**The premise, stated because it bounds the claim.** This project studies **remote inference at a fixed encoder/decoder partition**: the transmitter runs an encoder, the receiver owns the task head, and that split is *imposed* rather than chosen. The claim is therefore "the best way to transmit at this partition", not "the globally optimal task communication scheme". This matters because for ten-class classification the complete task output is four bits, so a transmitter permitted to run the whole classifier could send a label instead of any representation at all — and no amount of joint coding beats four heavily-protected bits. That is a real objection and it is answered by the premise, not by the measurements: the split is a property of the deployment (a receiver-owned or mutable task, an edge node too small to carry the head, an imposed split-computing architecture), and ER-12 reports the label-transmission bound explicitly so the reader can see what the premise costs rather than wondering whether it was noticed. Reconstruction is **not** offered as the answer here — §15 makes it a non-goal, so it cannot do that work.

Because a single learned-vs-classical gap conflates two distinct advantages — **task-aware representation** versus **joint coding** — the comparison of record is a three-way one: classical reconstruction pipeline, task-aware *digital* pipeline (ER-9), and learned JSCC. ER-4 and ER-9 together decompose the gap; without them the result cannot be attributed.

Two further claims are **not** made. The systems are compared at equal channel uses and equal average symbol power, which is equal transmitted energy under the stated model: the result is better accuracy at equal resources, **not** a measured energy saving. And no claim is made about beating published DJSCC results (§13).

The Tier 1 deliverable is this effect demonstrated, quantified and *attributed* on a simulated channel, against a baseline tuned in the baseline's own favour.

## 2. Success criterion and preregistered hypotheses

Completion and outcome are deliberately separated. A capstone commits to a defensible process, not to a favourable measurement.

**Tier 1 is complete** when both systems (and the ER-9 control) are implemented, validated (G-1, G-2, G-7), bandwidth-matched (BR-3), fully bit-accounted (BR-10, BR-11), evaluated at the operating point selected by the learned-blind rule in ER-3 (G-8), and reported with paired inference (ER-10) under this preregistered protocol. **Completion does not depend on which way the result falls.**

**The hypotheses**, each decided by the paired procedure in ER-10 and each reported either way:

- **H1 — low-SNR separation (primary).** Supported if the paired 95% interval for (learned − classical) top-1 accuracy lies strictly above zero at **three or more consecutive** SNR grid points at or below `params.channel.train_snr_db_fixed`. Consecutiveness is a preregistered run rule, not three independent tests; no per-point significance is claimed, and the rule is **stricter** than a single-point test rather than looser — see the family-wise error note below. Reported alongside it and preregistered as the effect size of record: `params.evaluation.h1_effect_size`, the mean paired accuracy difference over the whole region at or below `params.channel.train_snr_db_fixed`, with a `params.evaluation.ci` interval. The run rule decides H1; the scalar states how large the effect was, which a yes/no rule cannot (AM-3).
- **H2 — graceful versus cliff.** The comparison window is selected **on the validation split** and then frozen (DEC-12): among all pairs of grid points exactly `params.evaluation.cliff_window_db` dB apart, take the pair over which the **classical** system loses the most top-1 accuracy. On the test split both systems are then evaluated over exactly those endpoints. Supported if the classical system loses at least `params.evaluation.cliff_drop_pp` percentage points there while the learned system loses no more than `params.evaluation.graceful_drop_pp`, both applied to `params.evaluation.h2_thresholds_apply_to` and tested by `params.evaluation.h2_test` — a paired difference-in-differences over the bootstrapped trajectory, so H2 is decided by ER-10 like every other hypothesis rather than by comparing four point estimates by eye (AM-53). **The classical system here is `params.evaluation.cliff_reference_system`, the fully fixed separated curve of BR-16, not BR-4's adaptive curve**: BR-4 re-tunes at every SNR, so its curve is the upper envelope of many configurations and degrades in steps rather than cliffing, and the 30 pp threshold was preregistered against a sharper curve than an envelope produces. The classical half of this hypothesis is also **knowable at G-8 and learned-blind**, so `params.evaluation.h2_threshold_check_gate` requires the largest fixed-MCS validation drop to be recorded there: if it falls below `params.evaluation.cliff_drop_pp`, that is a recorded finding while no learned model yet exists, and any threshold change entered as an `AM` at that point is genuinely blind to the hypothesis it affects. The G-4 pilot curve MUST NOT be used to move these thresholds — that temptation arrives at W7 and is not blind. Rationale: the cliff is a property of the classical system, so the classical curve is what defines the window; selecting it on test would leave DEC-12's validation-only rule with exactly one hole; and because `params.channel.test_snr_grid_db` is irregularly spaced, "a 4 dB window" is well defined only as the set of endpoint pairs the grid actually admits, which code derives from the grid rather than reading from a hard-coded list (AM-1).
- **H3 — convergence.** Supported if the paired accuracy gap trends toward zero as SNR rises: `params.evaluation.gap_trend_test` — the weighted least-squares slope of the paired gap against SNR over the full test grid — is negative with a `params.evaluation.ci` interval excluding zero, **and** the gap at the low-SNR end is positive per `params.evaluation.h3_requires_positive_low_snr_gap`. The second clause is not decoration: a negative slope alone does not mean convergence toward zero, since a gap that starts at −5 pp and falls to −30 pp also has a negative slope and would have satisfied this hypothesis as originally written while describing the opposite of what it claims. H1 already establishes the sign at the low end, so the clause costs nothing to check (AM-39). The slope is bootstrapped over `params.evaluation.gap_trend_bootstrap_unit` rather than over 18 aggregated points, which share images and models and are therefore far from independent. Deliberately *not* "monotone at every point": measured curves fluctuate, and one grid point moving the wrong way by a fraction of an interval width is noise rather than a refutation, so a monotonicity rule would have no executable pass condition (AM-2). A **crossover is reported if observed but is not required**: at low bandwidth ratios the learned system is expected to dominate at every SNR, which supports H1–H3 and is not a failure. DEC-16 states how the operating point and the baseline's modulation adaptivity are chosen to make a crossover observable if one exists, and what is reported if it does not.
- **H4 — attribution.** Joint coding is credited only to the extent the learned system also exceeds the ER-9 task-aware digital control under the H1 rule. If it does not, the gain is attributed to task-aware representation and reported as such. The supported form of the claim is that **the residual advantage is consistent with an advantage from the learned analog joint interface, under the tested matched control** — not that the residual gain is *caused* by joint coding. Beating one scalar-quantised digital system does not exclude quantiser weakness or a limited entropy model as the explanation, and ER-9 is one control rather than the best possible digital system; overstating this would claim more than a single comparison can carry (AM-55).

**Family-wise error, recorded so it is not re-litigated.** H1's run rule is sometimes read as a multiple-comparisons problem — many candidate runs are examined, therefore the false-positive rate must be inflated. The arithmetic runs the other way. `params.channel.test_snr_grid_db` holds 13 points at or below `params.channel.train_snr_db_fixed`, so there are 11 candidate runs of three. Under the global null of no true difference anywhere, and with a one-sided per-point error of 0.025: if the points were independent the probability that any run of three all clears the interval is at most 11 × 0.025³ ≈ 1.7 × 10⁻⁴; if they were perfectly dependent it is 0.025. Both are stricter than the 0.05 a single point would carry. **Requiring a run is the multiplicity control, not a defect in it.** The cost is power rather than validity, which is the direction a preregistered primary hypothesis should err in (AM-4).

This note previously went on to claim that because adjacent points are positively dependent, the realised rate must *lie between* those two figures. That does not follow, and the correction is recorded rather than quietly dropped (AM-32). Positive dependence does not sandwich the answer: take four independent blocks of three consecutive points, each block all-or-nothing Bernoulli(0.025). Every marginal is 0.025, the structure is positively dependent, and the probability of some run of three is 1 − (1 − 0.025)⁴ ≈ 0.096 — roughly four times the "perfectly dependent" figure. The two calculations above are therefore two *examples*, not bounds. What is true is narrower and sufficient: under the dependence families that actually describe neighbouring SNR points — exchangeable or AR-1 Gaussian-copula structure, arising from shared models and shared images at neighbouring noise levels — the run probability interpolates monotonically between them. That is a modelling assumption, so `params.evaluation.h1_run_calibration` in ER-10 **measures** it instead: a sign-flip permutation over whole per-image trajectories preserves the across-SNR correlation and yields the null distribution of the longest run directly. The decision rule is unchanged; what changes is that its error rate is calibrated rather than argued.

**Outcome reporting.** Any combination of supported and unsupported hypotheses is a valid, complete Tier 1. ER-8 governs: a negative or partial result is reported with the same rigour as a positive one, and weakening the baseline to manufacture a result is prohibited.

## 3. Settled decisions

- **DEC-1** — **Dataset ladder.** The headline result targets Imagenette at 160px, with STL-10 at 96px as the sole fallback headline, invoked at G-8 if compute or a degenerate baseline forces it. **CIFAR-10 is a plumbing smoke path only** — shape checks, gradient flow, kill-and-resume, schema — and MUST NOT become a headline dataset. The reason is that 32×32 at ten classes is a resolution whose accuracy says nothing about the 160px headline, and that at the *smaller* ratios its budget falls below the JPEG 2000 codestream floor (BR-11), so its low-SNR behaviour there would be a format artifact rather than a channel effect. **Corrected, because the original rationale was arithmetically false and this specification's rationales are meant to be checkable:** it claimed the budget was below any container floor *at every ratio*, which DEC-16's addition of 16-QAM made wrong at the top of the ladder — CIFAR-10 at `r_1_2` with 16-QAM at rate 5/6 receives 640 bytes for a 32×32 image, which is 5 bpp and far above any floor. The decision is unchanged; only its stated reason is (AM-34). Dataset MUST be a configuration axis, never a code fork. Rationale: highest-resolution headline the hardware can carry, with one pre-agreed step-down, and no fallback that leads off a cliff.
- **DEC-2** — **Dual-head decoder.** One decoder carrying a reconstruction head and a classification head, trained with `loss = CE + λ·MSE`. Rationale: the accuracy curve and the "blurry but still task-correct" demo visual come from one model rather than two, at a measured accuracy cost (SR-9). Reversal ladder, cheapest first: (a) relax the reconstruction floor to `params.learned_system.lambda_psnr_floor_relaxed_db`, since §13 already makes reconstruction quality a non-goal; only if that also fails, (b) split into two models and record the change here. (b) roughly doubles the training budget and MUST NOT be taken after G-4 without re-planning the schedule.
- **DEC-3** — **Python primary.** Learned system and classical baseline are both Python; MATLAB appears only as non-blocking cross-checks (OPT-1..OPT-3). Rationale: one language, one CI path, no license dependency on the critical path.
- **DEC-4** — **Compute.** An RTX 4060 Mobile (8 GB) is the assumed trainer, with Colab/Kaggle free tier as overflow. University cluster access MUST NOT appear on any critical path. Consequence: checkpoint/resume (SR-10) and a measured compute budget (SR-11, G-7) are hard requirements, not conveniences.
- **DEC-5** — **Radio hardware deferred.** Tiers 2 and 3 are specified as capability requirements plus a budget range (HR-1), not a named device, and no purchase happens before G-5.
- **DEC-6** — **Required experiments.** Operating-point selection, core comparison, SNR-mismatch robustness, the task-training ablation, the task-aware digital control and the paired inference procedure are required (ER-1..ER-4, ER-9, ER-10). Rayleigh fading and the λ sweep are future work (FW-1, FW-2), but the extension points that admit them (SR-5, SR-8) are required now.
- **DEC-7** — **Demo styling.** The Streamlit demo and the thesis figures share one publication-grade plotting module (DR-4), so a demo screenshot is directly usable in the report.
- **DEC-8** — **Document structure.** This file is authoritative and self-sufficient: a reader who never runs the generator loses nothing. All other files under `spec/` are derived views.
- **DEC-9** — **Source codec.** The classical baseline of record uses **JPEG 2000**, not JPEG. Rationale: JPEG carries an irreducible container floor of roughly 250–290 bytes (quantisation tables, frame and scan headers) even with optimised Huffman tables, which **at the small ratios and low code rates** is a large or total fraction of the payload — Imagenette at `r_1_24` with QPSK at rate 1/3 receives 266 bytes in total, so the container consumes all of it; CIFAR-10 is starved across most of the ladder; and on STL-10 it makes the low-rate LDPC configurations infeasible outright, so the low-SNR "cliff" would be a file-format artifact rather than a channel effect. **Corrected for scope (AM-34):** this rationale previously said the floor consumed "most of Imagenette's budget" at the core ratio, which DEC-16's adaptive modulation made false — Imagenette at `r_1_3` with 16-QAM at rate 5/6 receives about 10.7 kB, against which 290 bytes is 2.7%. The argument survives where it matters, which is the noisy, bandwidth-starved end where H1 and H2 both live; it was simply stated too broadly. JPEG 2000 has no comparable floor and its rate control is fine-grained enough to land close under any budget. **Correction, recorded rather than quietly dropped:** this decision originally claimed JPEG 2000 "supports exact target-byte rate control, which also collapses the quality sweep to a direct budget solve". It does not, at least not through the tooling this project will use — OpenJPEG's `opj_compress` exposes a per-layer compression *ratio* (`-r`) and a per-layer *PSNR* target (`-q`), which are mutually exclusive, and neither guarantees an exact emitted byte count. BR-1 therefore drives it as a cached search whose emitted size is authoritative (AM-8). This weakens the convenience argument but not the decision: the container-floor argument above is the load-bearing one, and a `≤ budget` guarantee is all BR-3's equal-channel-uses claim ever needed. JPEG is retained as a **secondary reported curve** (`params.baseline.source_codec_secondary`) because it is what practitioners actually deploy, and BR-11 makes the overhead difference visible rather than hidden.
- **DEC-10** — **LDPC provenance.** **Sionna `2.0.1`** provides base-graph and lifting-size selection, encoding, rate matching and decoding; everything in `params.baseline.ldpc_impl_local` is implemented in this project, behind the adapter seam required by BR-14. Reasoning, recorded so it is not re-litigated: (a) Sionna 2.0.0 migrated PHY and SYS to PyTorch and no longer depends on TensorFlow, so the "second deep-learning framework" objection this decision originally carried was checked against the release notes and is **obsolete** — the environment stays single-framework and DEC-3 is satisfied; (b) the classical baseline is never trained, so the codec need not be differentiable, which makes correctness and throughput the only real criteria; (c) Sionna implements TS 38.212 rate matching, which is the genuinely error-prone part, but **not code-block segmentation**, which is why the local layer exists and is where the standards work for PR-3 actually lives; (d) `params.baseline.ldpc_decoder` is a Sionna built-in check-node update, so no custom callable and no scaling factor to justify. Rejected: implementing the whole chain locally — roughly a week landing at W3 with no slack, gating G-2 which gates everything, and a silent base-graph transcription error is the worst failure mode available; AFF3CT via `py_aff3ct` — a C++ build on WSL2, CPU-only marshalling per codeword, and a second toolchain on the critical path, which is now the only remaining DEC-3 violation among the candidates. **Note the scope of that rejection:** it rules AFF3CT out as the *runtime* implementation, not as a one-shot generator of BR-2's golden vectors. A fixture generator runs once, emits a `.npz` at `params.baseline.ldpc_golden_vector_file`, and never appears in CI or at runtime, so none of the objections above apply to it and DEC-3 is untouched — which is why it sits on `params.baseline.ldpc_golden_vector_source_ladder` despite being rejected here (AM-22). **That `.npz` is generated rather than committed (AM-25):** `params.baseline.ldpc_golden_vector_vendored` is false, so what this repository carries is the generator, the pinned source and its checksums, not third-party vector data. Also rejected: generic Python LDPC packages (`pyldpc`, ProtographLDPC) — Gallager/protograph codes rather than 5G NR, so they cannot satisfy G-2 or PR-3 at all; pyAerial — needs the Aerial SDK and a datacenter GPU. Fallback ladder: pin an earlier Sionna if 2.0.x proves unsound at G-2, then drop to `params.baseline.ldpc_impl_fallback` behind the BR-14 seam with the segmentation layer already written and tested. The version pin, golden-vector provenance and measured throughput are recorded at G-9.
- **DEC-11** — **Training-SNR protocol.** One model is trained **at `params.channel.train_snr_db_fixed`** for each ratio ER-3 names — `params.bandwidth.crossover_ratio`, `params.bandwidth.efficiency_ratio` and `params.bandwidth.low_ratio_operating_point`, at most three and two if the first two coincide — and evaluated across the whole test grid. Not one model per test SNR, not one per entry in `params.bandwidth.ratios`, and not SNR-randomised training — the last is required by ER-2 as a single-seed comparison rather than as this protocol, having been OPT-4 until AM-45 promoted it. Rationale: fixed-SNR training is what makes ER-2's mismatch profile meaningful, and it bounds the training count at one run per selected ratio per seed. This originally read "per bandwidth ratio", which implied a learned model at all five ratios; ER-3's selection rule is learned-blind by construction, so those extra runs could not have informed the decision they appeared to serve (AM-12).
- **DEC-12** — **Selection uses validation data only.** Every choice that could flatter a result — baseline codec quality and LDPC rate (BR-4), λ (SR-9), training checkpoint, operating ratio (ER-3), architecture — MUST be made on `params.datasets.*.val_images`, disjoint from the test split. The test split is touched once, for the frozen configuration. Rationale: `best config per test SNR` selected on test labels is test-set leakage and would invalidate every interval in §2.
- **DEC-13** — **Novelty position.** The course rubric scores novelty, while §15 disclaims beating published DJSCC results. These are reconciled by naming the contribution as one thing rather than two loose ones: **a reproducible, matched-channel-use comparison of image-digital, task-feature-digital and learned-JSCC transmission, with complete container and physical-layer bit accounting, evaluated under one common task protocol.** Its two load-bearing components remain (a) the ER-9 attribution decomposition separating task-aware representation from joint coding, and (b) the BR-11 format-overhead-controlled classical baseline. Reproduction quality carries the results marks; the decomposition and the accounting carry the novelty marks. **What is deliberately not claimed:** neither graceful degradation nor cliff-avoidance is novel — both are core findings of the earliest DeepJSCC work — and task-aware digital semantic systems, quantised semantic features and separate task-oriented source/channel schemes all have substantial prior art. The claim is the controlled three-way comparison and its accounting, not the existence of any one of the three systems. Claim (b)'s "which the DJSCC literature does not report" is **conditional on PR-1**: it is an assertion about the literature and MUST be verified by the completed review before it appears in the report, not asserted in advance from this file (AM-10). PR-7 makes this an explicit written deliverable rather than a viva improvisation.
- **DEC-14** — **Tiers 2 and 3 are stretch goals.** The expected and planned demonstration is **pre-recorded**; a live SDR replay or RPi demo is upside, not the baseline plan. Rationale: procurement lead time plus IQ framing, synchronisation, frequency offset and calibration (HR-6) is a second project, and HR-5 already makes Tier 1 standalone. Framing them as expected deliverables converts likely upside into apparent shortfall.
- **DEC-15** — **Pretrained weights prohibited for the reference classifier.** `params.reference_classifier` MUST be trained from scratch. Rationale: Imagenette is a subset of ImageNet, so ImageNet-pretrained weights are label leakage an examiner will spot immediately. `clean_acc_floor` values are set to from-scratch reality accordingly.
- **DEC-16** — **Crossover strategy, and its last-resort fallback.** A crossover requires the classical system's high-SNR ceiling to exceed the learned system's, which the original parameters made arithmetically impossible — the baseline was capped at QPSK, so its payload could not grow no matter how clean the link became, and both curves flattened into parallel lines (worked through in `docs/crossover-explained.md`). The remedy is to **remove an artificial cap on the baseline, never to weaken the learned system**: `params.baseline.modulations` gains 16-QAM and `params.baseline.modulation_tuning` makes modulation an adaptive axis of BR-4's per-SNR tuning, so the baseline transmits more per channel use as conditions improve, exactly as deployed systems do. Because BR-4 reports the best feasible configuration at each SNR, this strictly raises the classical curve at high SNR and cannot lower it at low SNR, so the cliff that H2 depends on is untouched. Governing rule: every lever used to obtain a crossover MUST either strengthen the baseline or be preregistered; handicapping the learned system to manufacture one is prohibited and would violate ER-8. **Fallback, last resort only:** if the adaptive baseline still does not cross by **G-10**, the project reports learned dominance across the whole grid, promotes the reconstruction-quality crossover to the secondary figure, and relies on §2, which already makes that a complete Tier 1. This fallback exists to keep the demo and the thesis intact, not as a preferred outcome; taking it MUST be recorded here together with the G-10 evidence that the adaptive baseline was genuinely attempted first. **The deciding gate is G-10, not G-8 (AM-33):** G-8 sits at W6, where ER-3's sweep is classical-only and the first learned model does not exist until W7's pilot, so there is no learned curve at G-8 and a gate there could not observe a crossover at all. G-8 selects ratios, which is all its learned-blind rule was ever able to do; G-10 decides this, at W10, once W8's training exists. **Supervisor position, recorded 2026-07-25:** pursue a crossover as hard as the rules allow, and fall back to reporting dominance across the grid if it genuinely does not appear. That is this decision's existing structure, now externally ratified rather than self-declared, and it converts the fallback from an author's convenience into an agreed outcome (AM-19). **It does not relax the governing rule and MUST NOT be cited as if it did.** "Try hard for a crossover" authorises strengthening the baseline and preregistering levers; it authorises nothing on the learned system's side of the comparison. Weakening the learned model, truncating the SNR grid before 16-QAM decodes, selecting the operating ratio on anything but ER-3's learned-blind rule, or reporting a fixed-modulation classical curve as the headline all remain prohibited under ER-8, and a crossover obtained by any of them would be worth less than no crossover at all.

## 5. System requirements (SR)

- **SR-1** — Every run MUST be fully determined by a configuration file derived from `params.generated.yaml`; no experiment-affecting constant may be hard-coded in source. *(verify: unit test asserting config round-trip, plus a lint rule flagging numeric SNR/k literals outside `src/config/` and tests)*
- **SR-2** — All datasets in `params.datasets` MUST be selectable by name through one code path, with no dataset-specific branching in the encoder, decoder or training loop (DEC-1). *(verify: unit test instantiating each dataset)*
- **SR-3** — For a configured dataset and ratio, the encoder MUST emit exactly the number of complex symbols given by `params.bandwidth.k_symbols`. *(verify: unit test on output shape for every dataset × ratio pair)*
- **SR-4** — Transmitted symbols MUST satisfy `params.bandwidth.power_constraint` per image via an explicit normalisation layer, so SNR is unambiguous. *(verify: unit test that empirical mean power is 1.0 ± 1e-3)*
- **SR-5** — Channel models MUST live behind a registry exposing `forward(x, snr_db)` and be selectable by name. `params.channel.models_supported` is required now; `params.channel.models_planned` MUST be addable without modifying encoder, decoder or training code (FW-1). *(verify: unit test registering a stub channel and training one step through it)*
- **SR-6** — The channel MUST be differentiable end-to-end; gradients from the loss MUST reach encoder parameters. *(verify: unit test asserting non-zero encoder gradients after one backward pass)*
- **SR-7** — Noise power MUST be derived from `params.channel.snr_definition` alone, and the same definition MUST be used by the learned system, the baseline and the hardware tiers. *(verify: unit test measuring empirical SNR against the requested value)*
- **SR-8** — The decoder MUST carry both heads in `params.learned_system.decoder_heads`, trained as `params.learned_system.loss` with λ read from config (DEC-2). Setting λ = 0 MUST yield a pure-task model without code changes (FW-2). *(verify: unit test on both head outputs and on λ=0 disabling the MSE term)*
- **SR-9** — λ MUST be calibrated at G-4, **on the validation split** (DEC-12), to the smallest value in `params.learned_system.lambda_grid` whose top-1 accuracy at `params.learned_system.lambda_calibration_snr_db` is within `params.learned_system.lambda_acc_tolerance_pp` of the λ=0 model while reconstruction PSNR at `params.learned_system.lambda_psnr_eval_snr_db` is at least `params.learned_system.lambda_psnr_floor_db`, falling back to `params.learned_system.lambda_psnr_floor_relaxed_db` before any DEC-2 model split. Calibration happens at `params.learned_system.lambda_calibration_ratio` and the chosen λ transfers to the other ratios DEC-11 trains. Those three parameters replace the phrases "the core SNR" and "15 dB SNR", which named no parameter at all and were bare numeric literals of exactly the kind SR-1's own lint rule exists to flag — the requirement and its linter disagreed (AM-35). DEC-2's relaxed PSNR floor exists partly to absorb λ's transfer to smaller ratios, where the floor is harder to clear. The chosen value MUST replace `params.learned_system.lambda_core` in this file and clear `lambda_status`. The search is one pilot training run per grid entry at a single seed, so G-4's cost is bounded in advance rather than open-ended; and because λ sits in the training objective, the final multi-seed training of §13 MUST happen **after** this gate, never before it (AM-7). *(verify: calibration run archived under `params.artifacts.results_dir`, one row per `params.learned_system.lambda_grid` entry)*
- **SR-10** — Training MUST checkpoint every `params.compute.checkpoint_every_epochs` epochs and resume from checkpoint with no metric discontinuity, so runs survive Colab/Kaggle session limits (DEC-4). *(verify: kill-and-resume test comparing loss curves across the seam)*
- **SR-11** — A profiling run at `params.compute.profiling_gate` MUST establish the achievable batch size, epoch time and peak memory on `params.compute.primary_device`; thereafter no scheduled run may exceed `params.compute.max_wall_clock_hours_per_run` or `params.compute.vram_budget_gb`, and sweeps MUST be decomposable into independent runs each meeting those bounds. `params.learned_system.batch_size` is a target, not a constraint: gradient accumulation per `params.learned_system.grad_accumulation_allowed` MAY be used to hold the effective batch size. *(verify: profiling report archived, and measured wall clock and peak VRAM logged per run)*
- **SR-12** — Runs MUST be deterministic given a seed: on the same pinned software environment and hardware class, the same seed and config reproduce reported metrics within 0.5 percentage points; across environments, reproduction is required only within the reported interval. The lockfile, CUDA and driver versions MUST be recorded with the results. *(verify: repeat-run test on the pinned environment plus an archived environment manifest)*
- **SR-13** — Every result row MUST record its `run_id`, `git_commit`, `git_dirty` and `config_hash`, and artifacts MUST be written under the directories in `params.artifacts`. *(verify: schema test on emitted CSV)*
- **SR-14** — The learned model MUST NOT exceed `params.learned_system.max_params_millions` million parameters. The binding justification is `params.learned_system.max_params_policy`: encoder, decoder and head together MUST NOT exceed the parameter count of `params.reference_classifier`, so the learned arm is never larger than the network scoring the classical arm. This replaces the original rationale — "keeping the RPi tier plausible" — which rested a Tier 1 constraint on a stretch tier that DEC-14 makes explicit upside and HR-5 forbids any Tier 1 requirement from depending on. The numbers happen to coincide: a ResNet-18 at ten classes is about 11.2M parameters, so the 10M cap is already below its own comparator and the re-justification costs nothing (AM-36). *(verify: unit test on parameter count, asserting both the absolute cap and that it does not exceed the measured reference-classifier count)*
- **SR-15** — The downstream task head MUST sit behind a registry so a different task can be added without touching the encoder, channel or training loop (FW-4). *(verify: unit test registering a stub task head)*
- **SR-16** — Peak-to-average power ratio MUST be measured and reported per `params.learned_system.papr_report_required` for **all three systems**, not the learned one alone — adaptive 16-QAM is not constant modulus either, so reporting the learned arm's PAPR in isolation invites the reader to assume the digital arms are at 0 dB. A peak-power/clipping constraint MUST be available per `params.learned_system.peak_power_constraint_available`, and per `params.learned_system.papr_constrained_variant_required` a PAPR-constrained learned variant MUST be trained and reported as a secondary curve at `params.bandwidth.headline_ratio` over `params.learned_system.papr_constrained_variant_seeds` seed. Rationale: an average-power constraint lets a learned encoder buy SNR with peaky symbols that a constant-modulus scheme cannot use and a real amplifier cannot deliver; unreported, this is an unearned advantage in simulation and a Tier 2 discrepancy on hardware. Disclosure alone answers "did you know?" but not "is the comparison fair?", and this is the first objection a reader with a communications background reaches for — one extra training run converts it into a figure this project produced itself (AM-44). Reported PAPR is the **symbol-domain** peak-to-average ratio; oversampled waveform PAPR after pulse shaping is a different and larger quantity, and the two MUST NOT be conflated in the report. *(verify: PAPR logged in every result row for every system, a unit test that the clipping constraint bounds measured PAPR, and the constrained variant present as a distinct `system` value)*
- **SR-17** — A validation split MUST be carved per `params.evaluation.split_rule` from each dataset's `val_images` count and used for **every** selection decision — baseline configuration, λ, training checkpoint, operating ratio, architecture (DEC-12). The test split MUST NOT be read by any selection code path. *(verify: unit test asserting split disjointness, and an audit that no selection routine can reach the test loader)*
- **SR-18** — Every evaluation run MUST emit a per-image outcome file matching `params.artifacts.per_image_schema` under `params.artifacts.per_image_dir`, keyed by `run_id`. A `run_id` MUST be unique per `params.artifacts.run_id_key` — the tuple that makes it one. Aggregate rows alone cannot support the paired inference in ER-10, and ER-10 pairs per-image outcomes across systems at matched (image, SNR, seed) *entirely through `run_id`*, because `params.artifacts.per_image_schema` carries none of those columns itself. Left undefined, the join is unspecified and the pairing silently wrong (AM-37). *(verify: schema test; a test that recomputing `top1_acc` from the per-image file matches the aggregate row; and a test that no two result rows share a `run_id` with differing `params.artifacts.run_id_key` values)*
- **SR-19** — One canonical image MUST be defined per `params.preprocessing` and produced **before** either pipeline sees the data: `canonical_image`, `resize_interpolation`, `antialias`, `train_crop`, `eval_crop`, `colour_space`, `bit_depth` and `tensor_range`, with `eval_augmentation_permitted` false and `channel_normalisation` applied inside the model rather than in the pipeline. The classical codec MUST compress `params.preprocessing.codec_input` — the same canonical pixels the learned encoder receives — so BR-3's equal-channel-uses claim is not quietly comparing two different images. Reconstructions MUST be clipped per `params.preprocessing.reconstruction_clipped_before_metrics` before scoring, and PSNR and SSIM MUST use `params.preprocessing.psnr_data_range`, `params.preprocessing.ssim_impl` and `params.preprocessing.ssim_gaussian_weights`. Rationale: none of this was specified anywhere, and every item on the list changes a reported number — an unclipped reconstruction inflates PSNR, a mismatched `data_range` shifts it by decibels, and a codec fed differently-resized pixels from the encoder makes the whole comparison invalid rather than merely noisy (AM-28). *(verify: unit test asserting the canonical tensor is bit-identical on both paths for the same image index, plus a metrics test against a known-PSNR image pair)*

## 6. Baseline requirements (BR)

The baseline exists to be beaten honestly. Every requirement here is a defence against an unfair comparison.

- **BR-1** — The classical chain MUST be `params.baseline.source_codec` → `params.baseline.channel_code` → modulation → the same channel implementation the learned system uses. The codec MUST emit `params.baseline.j2k_container` and MUST be driven per `params.baseline.j2k_rate_control` via `params.baseline.j2k_rate_control_method`: the encoder is asked for a compression ratio, the emitted file is measured, and per `params.baseline.j2k_emitted_size_authoritative` **that measured size — not the requested ratio — is what counts against the budget**. The requirement is a codestream that does not exceed the payload budget, never one that exactly equals it; residual slack MUST be carried as filler and reported, not discarded (AM-8). **The codec configuration is frozen here rather than left to defaults (AM-51),** because BR-4's codec-rate axis is the outer loop of the largest cached artifact in the project and was previously unspecified in every respect: `params.baseline.j2k_impl` at `params.baseline.j2k_impl_version` driven through `params.baseline.j2k_binding`, with `params.baseline.j2k_wavelet`, `params.baseline.j2k_progression_order`, `params.baseline.j2k_resolutions`, `params.baseline.j2k_code_block_size` and `params.baseline.j2k_tile_size` fixed. The search is `params.baseline.j2k_search_method` within `params.baseline.j2k_search_bounds`, to `params.baseline.j2k_search_tolerance_bytes` and at most `params.baseline.j2k_search_max_iters` iterations, with `params.baseline.j2k_nonmonotone_policy` covering the case where emitted size does not fall monotonically with the requested ratio. **The search MUST be cached by `params.baseline.j2k_cache_key`** — the emitted codestream depends only on the image and the budget, so it is reusable across SNRs, seeds and every system sharing that budget; without the cache a naive implementation re-encodes on the order of 200,000 times in ER-1 alone, and the binding exists so that cost is not paid as process spawns. A **downsampling axis** `params.baseline.downsample_axis_px` is selected per `params.baseline.downsample_selection`: low-bitrate classical codecs often gain substantially from encoding a smaller image and upsampling at the receiver, and withholding that from the baseline would be exactly the artificial handicap DEC-16's governing rule forbids. The JPEG secondary curve is likewise pinned by `params.baseline.jpeg_impl`, `params.baseline.jpeg_chroma_subsampling` and `params.baseline.jpeg_optimise_huffman`. `params.baseline.source_codec_secondary` MUST be reported as a labelled second curve, not substituted for the first (DEC-9), and it is sufficient to report it at `params.bandwidth.headline_ratio` for one entry in `params.evaluation.train_seeds` — it is context for what practitioners deploy, not a hypothesis-bearing curve (AM-13). It previously pointed at the retired core_ratio, which after AM-20 was selected by no gate at all (AM-26). *(verify: integration test asserting the shared channel object; a test that every emitted codestream is ≤ its budget with the slack logged; and both codec curves present in the results CSV)*
- **BR-2** — The LDPC chain MUST be validated two ways before any learned-vs-classical comparison is reported. **Bit-exactly**: encoder output and rate-matched output MUST reproduce `params.baseline.ldpc_golden_vector_file`, a fixture generated from an implementation independent of `params.baseline.ldpc_impl` whose provenance is fixed at `params.baseline.ldpc_golden_vector_source_gate` by descending `params.baseline.ldpc_golden_vector_source_ladder` until one rung is confirmed available. The ladder exists because the MATLAB licence is being attempted but is **not assured** (AM-22), and BR-2 gates G-2 which gates every reported comparison, so a single-sourced fixture would put the whole comparison behind a licence decision the project does not control. **Rung 2 is confirmed and demonstrated at W0 (AM-25),** and `params.baseline.ldpc_golden_vector_source_rung` records it as the rung in use. Two corrections to what this requirement previously assumed. First, srsRAN does **not** commit its vector data to git: the `.dat` files are published per release as `params.baseline.ldpc_golden_vector_upstream_asset`, and `params.baseline.ldpc_golden_vector_upstream_url` pins the immutable release named by `params.baseline.ldpc_golden_vector_upstream_release`. Second, the licence question is answered by **not vendoring**: `params.baseline.ldpc_golden_vector_vendored` is false, so the fixture is built by a committed fetch-and-convert script that verifies `params.baseline.ldpc_golden_vector_sha256` and writes `params.baseline.ldpc_golden_vector_file`, which stays out of git. Checksums are facts about a file rather than a copy of it, so this keeps byte-exact reproducibility without redistributing AGPLv3 data in a submitted artifact, and `params.baseline.ldpc_golden_vector_licence_check_required` is thereby satisfied rather than deferred. Because that path needs the network, `params.baseline.ldpc_golden_vector_offline_floor` MUST also be committed and MUST run unconditionally: a hand-derived small-lifting-size case, wholly this project's own work, so the bit-exact test never silently skips when a fetch fails or upstream disappears. The rung actually used MUST be recorded with the fixture. **The comparison is not bit-for-bit naive, and the alignment MUST be implemented as follows** — established by running it at W0, where a wrong alignment agreed with the reference at 0.50, which is chance and is exactly what a broken fixture would look like: srsRAN stores the codeword with the first 2Z systematic bits **already punctured** (BG1's codeword is 68Z, the stored buffer is 66Z), and marks filler positions with the byte 254, whereas `params.baseline.ldpc_impl` deletes filler positions *before* puncturing. Aligning therefore means dropping the 254-marked positions and nothing else, then truncating to a length whose rate stays above the base graph's minimum, then pinning the lifting size rather than letting the library infer it from (k, n). With that alignment the two agree **exactly**, on every case where the comparison is structurally valid. **Statistically**: measured BER/BLER MUST match published `params.baseline.ldpc_standard` curves **for every entry in `params.baseline.modulations` that BR-4 may select**, with every reference curve converted to this project's SNR convention using `params.channel.snr_conversion` and the conversion shown in the archived artifact. Higher-order modulations need soft-demapping to log-likelihood ratios rather than a sign decision, so an unvalidated 16-QAM demapper would silently degrade the baseline — the opposite of BR-4's intent and a direct threat to DEC-16. Rationale: a curve overlay is a judgement call and a fixture is a test, so the golden vectors are what turn G-2 into a red/green signal; and separately, a missed Eb/N0-to-Es/N0 conversion shifts rate 1/3 and rate 5/6 by about 4 dB *relative to each other*, which inverts BR-4's rate selection rather than merely offsetting the curve. *(verify: passing golden-vector test, plus an archived BER-vs-SNR plot with reference curve overlaid and the conversion arithmetic stated)*
- **BR-3** — The baseline MUST receive exactly the same number of complex channel uses `k` as the learned system, per `params.baseline.budget_rule`. Bandwidth matching is counted in channel uses, not in bytes. *(verify: unit test counting emitted symbols for both systems)*
- **BR-4** — At each SNR the baseline MUST be tuned in its own favour — sweeping codec target rate (or `params.baseline.jpeg_quality_grid` for the secondary curve) × `params.baseline.ldpc_rates` × `params.baseline.modulations` per `params.baseline.modulation_tuning`, and taking the **best feasible** configuration per `params.baseline.tuning` — with the selection made **on the validation split** and then frozen for the test evaluation (DEC-12). Modulation is an adaptive axis rather than a fixed choice (DEC-16): capping it would leave the baseline unable to exploit a clean link, which is an artificial handicap rather than a fair comparison. Reporting a single fixed configuration across all SNRs is prohibited. The sweep MUST be computed as a cached feasibility table plus per-(rate, SNR, blocklength) block-error characterisation composed analytically, not as a full per-image channel simulation of every cell. **The composition function is written down here rather than left to the implementer (AM-51),** since every selection in the project flows through it. Under a transport-block CRC one failed code block kills the transport block, so P(TB success) is the product over code blocks of (1 − BLER(E_r, K_r, SNR, modulation)), and expected accuracy at an SNR is P(TB success) × acc_clean(codec configuration) + (1 − P(TB success)) × 1/classes, with the outage term following BR-13. That makes `acc_clean` at each candidate codec configuration a **required measured input** — the classifier's accuracy on the validation split at each cached quality — which is a real artifact and MUST be produced rather than assumed. Block-error rates are characterised over `params.baseline.bler_characterisation_trials` trials per cell. **Selection runs in two passes and then stops (AM-54):** pass one selects under BR-8's clean-trained classifier, which is the only one that exists at that point; BR-12 then trains on the corpus those selections define; BR-12 re-scores the **cached** sweep table and re-selects once; and iteration terminates there, per `params.reference_classifier.br4_selection_terminates_after_pass`. Rationale: selecting under a classifier that is then replaced leaves the baseline tuned for a scorer nobody reports, and because the artifact-finetuned classifier tolerates heavier compression it would plausibly prefer a different point — spending the savings on stronger channel coding. Reporting the classical arm at a configuration chosen by the weaker scorer understates it, which is the direction ER-8 and DEC-16's governing rule both forbid. The second pass is cheap because `params.baseline.j2k_cache_key` makes it classifier forward passes over already-emitted codestreams rather than a re-encode, and terminating at two passes is preregistered so the loop cannot be run until it flatters a result. **Analytic composition is for selection only.** Once the per-SNR configuration is frozen, the reported test evaluation MUST be an actual per-image channel simulation sharing BR-7's noise draws, because BR-7 requires identical noise realisations across systems and ER-10 requires per-image paired outcomes — neither of which an analytic block-error rate can supply (AM-16). *(verify: sweep artifact showing the selected config per SNR, its provenance on the validation split, and the composition method; plus a test that every row feeding ER-10 carries a per-image outcome traceable to a simulated noise draw)*
- **BR-5** — If no codec configuration produces a file fitting the payload budget, the transmission MUST be recorded as infeasible, counted in `infeasible_rate`, and scored per BR-13, never silently skipped. Two distinct causes MUST be distinguished in `outage_reason`, because they are different findings: **codec infeasibility**, where a transport block exists but no codestream fits inside it, and **structural infeasibility**, where the channel budget cannot carry `params.baseline.tb_crc` plus a single payload byte, so there is no transport block to fill. The second is not hypothetical — adding `r_1_48` created one such cell, on the smoke dataset at BPSK rate 1/3, where a 21-bit budget leaves 5 bits after the CRC (AM-41, recomputed under AM-49's conditional CRC, which rescued the second of the two cells the unconditional 24-bit CRC had starved). A configuration in that state MUST be reported as structurally unavailable rather than as a codec failure, since reporting it as the latter would attribute a packetisation limit to JPEG 2000. *(verify: unit test at the smallest ratio where codec infeasibility is expected, plus a test asserting that a budget below the transport-block CRC is reported as structurally infeasible and never reaches the codec)*
- **BR-6** — A file that cannot be decoded after LDPC decoding MUST be scored per BR-13 and counted in `decode_failure_rate`. *(verify: unit test injecting an undecodable block)*
- **BR-7** — Both systems MUST see identical test images and identical noise realisations at a given seed and SNR. *(verify: test asserting bitwise-identical noise draws across the two pipelines)*
- **BR-8** — A frozen `params.reference_classifier` trained from scratch on clean images (DEC-15) MUST meet the headline dataset's `clean_acc_floor`, and the same instance MUST score every system in `params.reference_classifier.shared_by` — the classical reconstructions and the semantic reconstruction ablation (ER-4). It MUST NOT score ER-9, whose input is a feature stream rather than an image (AM-5). The smoke dataset's `clean_acc_floor` is advisory: DEC-1 makes CIFAR-10 a plumbing path, nothing in §2 depends on its accuracy, and gating the schedule on it buys risk for no result (AM-13). Its training recipe is `params.reference_classifier.{optimizer, lr, momentum, weight_decay, lr_schedule, lr_warmup_epochs, epochs, batch_size, label_smoothing, augmentation}` and MUST be read from config, not chosen in source: this classifier gates G-1, defines the "clean-image accuracy" that is the denominator of ER-3's entire selection rule, and scores one whole arm of the headline comparison, yet it carried no recipe at all — a direct SR-1 violation, and 0.88 from scratch on 8469 images is recipe-dependent rather than what a default loop returns (AM-27). *(verify: measured clean accuracy per dataset, archived, with a training log showing no pretrained initialisation, and a test that every element of the recipe is config-derived)*
- **BR-9** — The headline classical curve is the adaptive one produced by BR-4 over `params.baseline.modulations`. `params.baseline.core_modulation` defines the **fixed-modulation reference curve**, which MUST also be reported so the contribution of adaptive modulation is separable, and which is the like-for-like comparator for ER-9. It is **not** a cap on ER-9: ER-9's transport is tuned by BR-4's rule per `params.digital_semantic_control.transport_tuning`, over the same `params.baseline.modulations` and `params.baseline.ldpc_rates` the baseline may select. Rationale: ER-9 exists to *deny* the learned system credit for joint coding under H4, so pinning it to one modulation while the classical baseline may drop to BPSK at the noisy end — roughly 3 dB of reach, inside H1's region — would handicap the control in the one direction that makes H4 easier to support. That is the failure mode DEC-16's governing rule and ER-8 exist to prevent, and it applies to the control exactly as it applies to the baseline (AM-15). *(verify: config test, plus the adaptive classical curve, the fixed-modulation classical curve and ER-9's selected transport config per SNR all present in the results CSV)*
- **BR-10** — Bit accounting MUST be complete and normative: `params.baseline.tb_crc`, `params.baseline.cb_crc_bits`, code-block segmentation at `params.baseline.code_block_max_bits`, per-code-block rate-matching budget distribution (TS 38.212 §5.4.2.1 `E_r`), base-graph selection per `params.baseline.ldpc_base_graph`, and filler and rate matching per `params.baseline.rate_matching` all consume budget before any source byte does, exactly as in `params.baseline.budget_rule`. Partial final blocks and padding MUST be accounted, not discarded. The steps in `params.baseline.ldpc_impl_local` are implemented in this project rather than taken from `params.baseline.ldpc_impl`, which does not provide them (DEC-10). Rationale: without this the "equal channel uses" claim is disputable and the payload figure is wrong by a variable margin. Segmentation is unavoidable rather than optional at these budgets — Imagenette at the core ratio gives k=25600 symbols → 51200 channel bits → about 42,666 information bits at rate 5/6, which against `code_block_max_bits` 8448 and a 24-bit code-block CRC is six code blocks; even the low-ratio operating point needs two. **Verified arithmetically at W0 (AM-23), ahead of any implementation:** the §5.2.2 segmentation and §5.4.2.1 `E_r` allocation were computed against `params.generated.yaml` across all 72 live configurations — three operating ratios × two headline datasets × `params.baseline.modulations` × `params.baseline.ldpc_rates` — and every one distributes the channel budget with **exactly zero slack**, with every `E_r` a valid multiple of the modulation order. The canonical case reproduces this requirement's worked example: C = 6, K_r = 7135, E = [8532, 8532, 8534, 8534, 8534, 8534] summing to 51 200. Worth preserving because it is the trap: a naive `floor(G/C)` split yields 8533, which is **odd** and therefore not a legal `E_r` at all, since TS 38.212 requires a multiple of `N_L·Q_m`. **Confirmed against the library at W0 across all 180 configurations, with one correction (AM-24):** the info-bit budget MUST be clamped up to `params.baseline.ldpc_bg1_min_coderate` whenever `floor(G × rate)` would put the *per-code-block* rate `K_r/E_r` at or below it on base graph 1, which supports only coderate strictly above 1/3 because anything lower needs repetition coding. Three live configurations hit this — all at nominal rate 1/3, landing at 0.333281 against a limit of 0.333333 — and one of them is at `params.bandwidth.low_ratio_operating_point`, so it is not a corner case. The clamp moves the budget by a single bit (0.02%) and is therefore below any effect this project measures; what it does is make those configurations realizable at all. It MUST be evaluated after segmentation rather than on the transport block, because segmentation's own `ceil` already rescues most cases, and checking too early flags configurations that need no clamp. **Three conformance corrections (AM-49), none of which move a measured number but all of which the accounting claim depends on.** *(a)* The transport-block CRC is **conditional**, per `params.baseline.tb_crc`: TS 38.212 §7.2.1 uses CRC24A only when the payload exceeds `threshold_payload_bits` and CRC16 below it, where this specification carried an unconditional 24. Recomputed across the grid, 17 of the 72 live configurations fall below the threshold and are entitled to CRC16 — a byte of extra payload each, changing no segmentation and no `E_r`. *(b)* `params.baseline.code_block_max_bits` is **per base graph** — 8448 on BG1 and 3840 on BG2 — where a single 8448 was applied unconditionally; 14 of the 72 live configurations select BG2 under the standard. That this changed no segmentation is luck rather than design: every BG2 configuration here is small enough for one code block under either limit. *(c)* Base-graph selection is a property of the **transport block**, decided from (A, R) per `params.baseline.base_graph_selection_rule` *before* segmentation, and then applied to every code block. The W0 spike derived it *after* segmentation from the per-code-block rate, which is also what `params.baseline.ldpc_impl` does internally when left to infer — so `params.baseline.base_graph_pinned_at_seam` requires the graph to be selected here and passed explicitly through the BR-14 seam rather than inferred per codeword. `params.baseline.bg2_min_coderate` is recorded alongside `params.baseline.ldpc_bg1_min_coderate` because BG2 reaches 1/5 where BG1 stops at 1/3, and which floor applies now depends on a selection made before segmentation rather than after. AM-24's one-bit BG1 clamp is unaffected: all six clamped configurations have A above the CRC threshold and a rate above 0.25, so BG1 is correct for them under the standard's own rule. **Control plane (AM-43):** `params.baseline.control_plane_policy` declares modulation, code rate, payload length and quantiser width to be signalled out of band and excluded from the budget for **every** system. An adaptive receiver cannot decode without them, so leaving them unstated while claiming complete accounting is the one option that cannot be defended; excluding them symmetrically favours the classical baseline, which re-tunes per SNR and needs the signalling, over the learned system, which is frozen and needs none — the permitted direction under DEC-16's governing rule. *(verify: unit test reconciling emitted symbol count against k for several payload sizes including a single-block case, a partial final block, and a multi-block case; a test that the CRC width and base graph selected for each configuration match TS 38.212 §7.2.1 and §7.2.2; and an archived per-configuration record carrying A, CRC type, base graph, lifting size, code-block count, every `E_r`, filler bits and effective code rate)*
- **BR-11** — Container and header bytes MUST count against the budget per `params.baseline.container_policy`, and every baseline result row MUST report `header_bytes` and `payload_bytes` separately so the fraction of the budget spent on format overhead is visible at every operating point. Rationale: at these budgets container overhead is a first-order term, and an uncontrolled overhead difference would let a low-SNR "cliff" be a file-format artifact rather than a channel effect (DEC-9). *(verify: schema test on the two columns, and an archived overhead-fraction table per dataset × ratio × rate)*
- **BR-12** — A second `params.reference_classifier` instance, fine-tuned on codec-artifacted images, MUST also score the classical reconstructions, and both scores MUST be reported. It MUST be trained at `params.reference_classifier.artifact_finetune_gate`, **not earlier**, on `params.reference_classifier.artifact_finetune_corpus`. `params.reference_classifier.headline_scorer` names which of the two carries the headline numbers, and BR-4's second selection pass runs under it (AM-54). Rationale: scoring heavily-artifacted reconstructions with a classifier trained only on clean images measures domain shift as well as delivered information, and the learned system's head has no equivalent handicap because it trains on its own post-channel outputs. The gate matters because the artifact quality is not known until the operating ratio is selected (G-8) and BR-4 has chosen a codec configuration per SNR; and because BR-4 selects a *different* quality at each SNR, "the operating quality" is not one quality, so the corpus is the union of the qualities BR-4 selects across H1's region rather than a single point or one classifier per SNR (AM-6). *(verify: both scoring paths present as distinct `system` values in the results CSV, and a training log dated after the G-8 record)*
- **BR-13** — An outage — infeasible (BR-5) or undecodable (BR-6) — MUST be scored per `params.baseline.outage_policy` by drawing a label uniformly at random from the dataset's classes using the run's `channel_seed`, yielding a **binary** per-image outcome with expectation at chance level. Assigning a fractional accuracy is prohibited: it is not a per-image outcome and would break the paired inference in ER-10. A deterministic fallback — always predicting the training-split mode — was considered and **rejected**: it removes about half a percentage point of draw variance but costs the property that makes ER-10 work, since the random draw is reproducible from `channel_seed` and therefore identical across systems at a matched image, which is exactly what the pairing needs. What is adopted instead is the reporting half: every affected row MUST carry `coverage_rate` and `acc_given_delivery` alongside end-to-end `top1_acc`, so a reader can separate "the link failed" from "the link worked and the task failed" rather than seeing one number that conflates them (AM-38). *(verify: unit test that outage draws are reproducible under a fixed seed, that the empirical outage accuracy converges to 1/classes, and that end-to-end accuracy reconciles with coverage and conditional accuracy)*
- **BR-14** — `params.baseline.ldpc_impl` MUST sit behind an adapter exposing only the operations in `params.baseline.ldpc_impl_provides`, with every step in `params.baseline.ldpc_impl_local` implemented above that seam and unit-testable against a stub encoder. Substituting `params.baseline.ldpc_impl_fallback` MUST NOT require any change above the seam. Two library-facing details are fixed here rather than at the call sites, both measured at W0 (AM-24). **Spelling:** this specification names the check-node update `params.baseline.ldpc_decoder`, which the library rejects; `params.baseline.ldpc_decoder_impl_spelling` is the string it accepts, and the mapping between them lives at the seam. **Sign:** `params.baseline.ldpc_llr_convention` records that the library reads log-likelihood ratios as log(p(x=1)/p(x=0)), so the demapper MUST emit a **negative** LLR for the mapping x = 1−2c. This is the seam's most dangerous detail because it fails silently — with the sign inverted the decoder still runs, still returns exactly k bits, and still reports no error, while producing a measured BER of 0.77 at an SNR where the correct sign gives 0.00. An adapter conformance test MUST therefore assert clean decoding at high SNR, not merely that decoding returns. **Base graph:** per `params.baseline.base_graph_pinned_at_seam` the seam MUST pass the graph selected by BR-10 explicitly rather than letting the library infer it. `params.baseline.ldpc_impl` selects a base graph per *codeword* from its own (k, r), which reproduces TS 38.212 §7.2.2 arithmetic but applies it at the wrong granularity — the standard decides once per transport block and then uses that graph for every code block, so a small final block can diverge from the rest of its own transport block if inference is left on. The library accepts an explicit base-graph argument, so this costs one parameter at the seam and removes an entire class of silent non-conformance (AM-49). Rationale: this is what makes DEC-10's fallback ladder real rather than aspirational, and it mirrors the registry pattern already required for channels (SR-5) and task heads (SR-15). *(verify: unit test exercising the segmentation layer against a stub encoder, plus an adapter conformance test run against both implementations)*
- **BR-15** — The **adaptation asymmetry MUST be disclosed** wherever the headline comparison appears: the classical system is re-tuned at every SNR across codec rate, `params.baseline.ldpc_rates` and `params.baseline.modulations`, while the learned system is trained once per DEC-11 and evaluated frozen. Rationale: the asymmetry is deliberate and favours the baseline, which is what BR-4 exists to do — but it is also a large part of why any crossover appears, and an advantage handed to the baseline is still a confound if it goes unstated. Disclosed in advance it reads as rigour; discovered by an examiner it reads as a thumb on the scale. The asymmetry cuts **both** ways and the disclosure MUST say so: at high SNR the baseline's re-tuning lets it climb to 16-QAM, but at low SNR it lets the baseline fall back to BPSK rate 1/3 for roughly 3 dB of extra reach — squarely inside H1's region — while the learned model is frozen at a 7 dB training point and evaluated down to −8 dB, a 15 dB mismatch. That is the mechanism by which the primary hypothesis could fail for a design reason rather than a physical one, which is why ER-2 now **requires** the SNR-randomised variant that answers it with a curve rather than a paragraph (AM-45). *(verify: the asymmetry stated in the thesis methods section and in the caption of every headline figure, and the fixed-modulation reference curve of BR-9 present for comparison)*

- **BR-16** — A **fully fixed separated curve** MUST be reported: source codec configuration, LDPC rate and modulation all selected at `params.baseline.fixed_mcs_design_snr_db` on the validation split and then frozen across the whole of `params.channel.test_snr_grid_db`. This curve, named by `params.evaluation.cliff_reference_system`, is the reference for H2; BR-4's adaptive curve remains the fairness baseline for H1 and the headline comparison. Rationale: BR-4 re-tunes codec rate, code rate and modulation at every SNR, so its curve is the upper envelope of many configurations rather than one system's waterfall — an envelope degrades in *steps* as it falls back to more robust settings and only cliffs when it runs out of them. H2's `params.evaluation.cliff_drop_pp` threshold was set against a sharper curve than BR-4 will actually produce, and the classical cliff-versus-graceful comparison in the DJSCC literature is against a fixed separated configuration evaluated away from its design point, which is what this curve is. BR-9's fixed-*modulation* curve is insufficient for this purpose because source rate and LDPC rate still adapt within it. The accompanying prose MUST be narrowed to match: the claim is that *the selected fixed-rate, single-packet separated baseline* exhibits a waterfall, not that separated coding has a cliff in general — progressive JPEG 2000 packetisation or unequal error protection can itself degrade gracefully (AM-53). *(verify: the fixed-MCS curve present as a distinct `system` value across the full grid, its frozen configuration archived with its validation-split provenance, and H2 computed against it rather than against the adaptive curve)*

- **ER-3** — **Operating-point selection and bandwidth sweep.** Before the headline run, sweep every entry in `params.bandwidth.ratios` **with the classical system only**, on the **full validation split** at one seed, and select **two** operating points at G-8 by this preregistered, **learned-blind** rule applied at two thresholds: *the smallest ratio at which the classical system's high-SNR ceiling comes within `t` percentage points of its clean-image accuracy*, evaluated at `t` = `params.bandwidth.efficiency_ratio_threshold_pp` to give `params.bandwidth.efficiency_ratio`, and at `t` = `params.bandwidth.crossover_ratio_threshold_pp` to give `params.bandwidth.crossover_ratio`. Both are lookups against the same classical sweep table, so the second threshold costs nothing to evaluate, and the two MAY select the same ratio — in which case there is one operating point and `params.bandwidth.headline_ratio` resolves to it unchanged. **If no ratio satisfies the crossover threshold while some ratio satisfies the efficiency threshold**, `params.bandwidth.crossover_ratio` resolves to the largest ratio in `params.bandwidth.ratios`, `params.bandwidth.headline_ratio` resolves to `params.bandwidth.crossover_ratio_unsatisfiable_fallback` instead, and the absence of a 2 pp ratio is reported as a first-class finding under DEC-16's fallback. This is preregistered here rather than settled at G-8 because G-8 holds the classical sweep table in hand, and 2 pp is a demanding bar for a lossy codec scored by a clean-trained classifier — the asymmetric failure is the likely one, and G-8's existing fallback covers only the symmetric case where the rule fails at every threshold (AM-41). Rationale for two: the looser threshold locates the **efficiency point**, the tightest budget at which the baseline is still healthy, which is where the bandwidth claim lives; but "within 5 points of clean" admits a classical ceiling around 0.83 while the learned ceiling is estimated at 0.85–0.87, so that threshold can select a ratio at which no crossover exists at all. The tighter threshold locates the **crossover point**, the smallest budget at which the classical ceiling can actually overtake the learned one. Reporting both shows the trade-off as a function of budget rather than asserting it at a point (AM-20). The rule inspects only the classical system at either threshold, so it cannot be accused of selecting for the hypothesis; it places the comparison where the baseline is healthy rather than where it is starved, and tightening a threshold hands the baseline *more* budget, which DEC-16's governing rule expressly permits. Because BR-4 now adapts modulation as well (DEC-16), the classical ceiling rises faster with SNR than it would under a fixed modulation, so the rule is expected to select a *smaller* ratio than it otherwise would — the crossover is bought with better use of the budget rather than with more budget. The sweep also reports `params.bandwidth.low_ratio_operating_point` as the bandwidth-starved regime where dominance rather than crossover is expected. That point is resolved at G-8 by `params.bandwidth.low_ratio_rule` rather than read as a fixed value: it was hard-coded at `r_1_12` while `params.bandwidth.headline_ratio` is selected, so if the rule selects a smaller ratio than `r_1_12` the "starved" point sits *above* the operating point and the regime it names does not exist — leaving §2's expectation of low-ratio dominance with no experiment behind it (AM-41). For the same reason the ladder MUST NOT be allowed to saturate at its bottom: per `params.bandwidth.ladder_bottom_saturation_rule`, if the rule selects the smallest ratio in `params.bandwidth.ratios` the ladder MUST be extended downward and the classical-only sweep re-run before the selection is recorded. `r_1_48` was added for this reason and is free architecturally — it is exactly one complex channel at the 4x-downsampled grid on all three datasets, where `r_1_32` would need 1.5 and is therefore not usable. Because the rule is learned-blind, learned systems MUST be trained at `params.bandwidth.crossover_ratio`, `params.bandwidth.efficiency_ratio` and `params.bandwidth.low_ratio_operating_point` **only** — at most three ratios, and two if the thresholds coincide — nothing in §2 needs a learned model at every ratio, and training five would spend roughly nine runs to inform a decision that cannot see them (AM-12). The sweep uses the full validation split rather than `params.evaluation.test_subset_size`: that parameter sizes a subset of the *test* split under ER-6, and at 2000 it exceeds the `val_images` count of every dataset in `params.datasets`, so the requirement as previously written could not be executed at all (AM-14). *(verify: results CSV + figure, an archived record of the rule's evaluation at every ratio, and an assertion that no learned-system row exists at a ratio outside the ratios named here — previously "the two named here", which contradicted this requirement's own body naming three, a stale clause AM-20 left behind (AM-26))*

- **ER-9** — **Task-aware digital control.** A third system MUST be built and evaluated at matched `k`, sharing every element in `params.digital_semantic_control.shared_with_learned` with the learned JSCC system and differing from it **only** in `params.digital_semantic_control.differs_only_in`: features taken at `params.digital_semantic_control.transmit_layer` are quantised per `params.digital_semantic_control.quantiser` at a width selected from `params.digital_semantic_control.quantiser_bits_grid` on the validation split (DEC-12), entropy-coded per `params.digital_semantic_control.entropy_coder`, and carried over the same `params.baseline.channel_code` chain as the classical baseline with its transport configuration tuned per `params.digital_semantic_control.transport_tuning`. Charging it would weaken the control on every image and make H4 easier to support, which is the wrong direction to be wrong in. - **ER-10** — **Paired inference.** The §2 hypotheses MUST be decided on **paired per-image outcomes** (SR-18), not on the overlap of two independent intervals: `params.evaluation.paired_test` for the point decision and `params.evaluation.ci` with `params.evaluation.bootstrap_resamples` for the interval on the accuracy *difference*, with the image-level bootstrap nested inside the seed hierarchy. Each seed cell is a **compound replicate** per `params.evaluation.seed_cell_interpretation`, and no claim is made that `params.evaluation.train_seeds` and `params.evaluation.channel_seeds` contribute as *separate* variance components. This requirement previously promised exactly that, which AM-17 made unachievable in the same round it was written: `params.evaluation.seed_pairing` zips the seeds into (0,0), (1,1), (2,2), so training luck and channel luck move together in every cell and no analysis can attribute a difference to one rather than the other. Three diagonal cells cannot separate two sources — the honest statement is that each cell is one combined replicate, and the per-seed curves below are what show the spread. Crossing the seeds into nine cells would restore the decomposition at roughly three times ER-1's evaluation cost, and was rejected because two degrees of freedom could not support the claim even then (AM-31). Rationale: both systems see identical images and noise draws, so a paired test is both the natural and the far more powerful analysis — a three-seed Student-t interval has two degrees of freedom and would demand roughly a five-point gap to clear non-overlap. Three further rules make the seed hierarchy honest, since `params.evaluation.bootstrap_resamples` resamples images and cannot manufacture training-run evidence that three seeds do not contain (AM-11): the **classical arm has no training-seed dimension** — it is never trained — so the training-seed variance component belongs to the learned arm alone and a classical result MUST NOT be replicated across seed cells and counted as independent baseline runs; `params.evaluation.paired_test` MUST be computed **within** a seed cell and never pooled across cells, which would treat repeated measurements of the same images as independent; and each seed's accuracy-vs-SNR curve MUST be reported separately alongside the between-seed range, so the reader sees training-run spread rather than inferring it from an interval that mostly reflects image count. ER-10 also computes `params.evaluation.h1_effect_size` and `params.evaluation.gap_trend_test` for §2's H1 and H3. Two further computations are required. **H1's run rule MUST be calibrated, not merely argued**: `params.evaluation.h1_run_calibration` over `params.evaluation.h1_run_permutation_resamples` resamples gives the null distribution of the longest run of positive intervals by sign-flipping whole per-image trajectories, which preserves the across-SNR correlation that makes the analytic argument in §2 a model assumption rather than a bound. The per-image outcomes SR-18 already requires are exactly the input this needs, so it is a few dozen lines beside a bootstrap that already runs (AM-32). **H3's slope MUST be bootstrapped over `params.evaluation.gap_trend_bootstrap_unit`** — per-image, per-seed trajectories — rather than over 18 aggregated SNR points, which are strongly correlated through shared images and shared models and would give an interval far too narrow (AM-39). *(verify: inference script reproducing every reported interval from the per-image files, with a unit test on synthetic data of known effect size, a test that no pooled-across-seeds McNemar statistic is emitted, and an archived permutation null distribution for the run statistic)*
- **ER-11** — **Bandwidth versus accuracy.** The learned system MUST be evaluated at **every** ratio DEC-11 trains it at — not `params.bandwidth.headline_ratio` alone — across `params.channel.test_snr_grid_db`, at sweep strength per ER-6 and one entry in `params.evaluation.train_seeds`, with the classical curve at the same ratio, and reported as the bandwidth-versus-accuracy figure. DEC-11 trains up to three ratios, but ER-1 runs at the headline ratio alone, ER-2 names no ratio and ER-4 is an ablation of existing rows — so the `params.bandwidth.efficiency_ratio` and `params.bandwidth.low_ratio_operating_point` models were trained and then consumed by no requirement, no figure and no hypothesis. ## 15. Non-goals

Explicitly out of scope. Listed so that scope creep is a visible spec change.

- Bit-exact or perceptually-optimal reconstruction as an objective in its own right — reconstruction exists to serve the task and the demo.
- Reinforcement learning of any kind. The system is trained end-to-end by supervised gradient descent.
- Multi-user, MIMO, relay or interference channels; a single point-to-point link is assumed.
- Video, audio or real-time streaming sources.
- On-device training or adaptation; edge nodes run frozen models.
- Adversarial robustness, security or privacy of the learned representation.
- Beating state-of-the-art DJSCC results. The comparison of record is against the classical baseline, not against the literature; the novelty claimed is the attribution decomposition and the overhead-controlled baseline (DEC-13, PR-7), not headline numbers.
- Energy measurement. The systems are matched on channel uses and average power, which is equal transmitted energy by construction; no power-meter claim is made (§1).

**Process rule (AM-47).** An amendment that changes what a parameter *means* — not merely its value — MUST state which sections were re-read against it, and **§13 and every `verify` clause are always on that list**. Rationale: AM-14 established that the generator's arithmetic check cannot catch cross-section inconsistency, because a stale citation still resolves. That lesson has since cost four further defects across two rounds — AM-26, AM-31, AM-33 and the schema half of AM-38 — and every one was an amendment correctly applied where it was noticed and never propagated to the schedule or to a verify clause. **Amendment round 1 — 2026-07-25, pre-W0.** Sources: `EXT-3`, a full-specification review by ChatGPT returning a "commit but do not freeze" verdict; and `INT-1`, the internal audit run while adjudicating it. Roughly a third of `EXT-3` was adopted. Its central statistical objection (that H1's run rule has an inflated false-positive rate) was rejected on the arithmetic in AM-4, and three of its recommendations restated decisions already settled in DEC-10, DEC-14 and G-9. `INT-1` found five further defects, two of which — AM-14 and AM-15 — were more consequential than most of `EXT-3`.

- **AM-1** — **H2's comparison window was undefined.** Changed: §2 H2 now selects the window on the validation split, using the classical curve, over the endpoint pairs the grid admits at `params.evaluation.cliff_window_db`, then freezes those endpoints for the test evaluation; added `cliff_window_db` and `cliff_window_selection` to the evaluation parameters. Why: "the steepest 4 dB window of the grid" named neither the curve that defines steepness, nor the split it is chosen on, nor how an irregularly-spaced grid admits a 4 dB window at all — so H2 could have been settled after seeing test results, which is the one place DEC-12's validation-only selection rule had a hole. Raised by: EXT-3.
- **AM-2** — **H3 had no executable pass condition.** Changed: §2 H3 replaces "contracts monotonically (within interval width)" with a negative weighted-least-squares slope of the paired gap against SNR whose bootstrap interval excludes zero; added `gap_trend_test`. Why: strict monotonicity is refuted by any single point of measurement noise, and "within interval width" did not say how much deviation was tolerated, so H3 had no red/green answer and would have been argued rather than decided. Rejected alternative: EXT-3 proposed demoting H3 to exploratory, which discards a claim that costs one regression to state properly. Raised by: EXT-3 (diagnosis), INT-1 (remedy).
- **AM-3** — **H1 reported no effect size.** Changed: §2 H1 keeps the three-consecutive-point run rule as the decision procedure and adds `h1_effect_size`, the mean paired accuracy difference across the whole region at or below `params.channel.train_snr_db_fixed`, reported with a `params.evaluation.ci` interval. Why: the run rule answers whether there is separation but never how much, and a single preregistered scalar over a fixed region is both the number a reader wants and immune to any objection about run structure or window selection. Raised by: EXT-3 (as a replacement for H1; adopted as an addition instead, per AM-4).
- **AM-4** — **H1's run rule was defended rather than replaced.** Changed: §2 gains a family-wise error note stating the bound explicitly; H1's decision rule is unchanged. Why: EXT-3 argued the rule scans 11 candidate runs and therefore inflates the false-positive rate, and recommended replacing it with a simultaneous bootstrap band or a single scalar. Why: BR-4 re-tunes codec rate, code rate and modulation at every SNR, so its curve is the upper envelope of many systems — an envelope degrades in *steps* as it falls back to more robust settings and only cliffs once it runs out of them, whereas `params.evaluation.cliff_drop_pp` was preregistered against a single configuration's waterfall. BR-9's fixed-*modulation* curve does not fix this, because source rate and LDPC rate still adapt within it. Separately H2 stated numeric thresholds but never said how uncertainty governs support, while §2 claims every hypothesis is decided by ER-10. The threshold check is placed at G-8 because the classical half of H2 is knowable there and **learned-blind**: if the largest fixed-MCS validation drop is already below 30 pp, that is a finding recorded while no learned model exists, and any amendment made then is genuinely blind to the hypothesis it affects — which it would not be at W7. Raised by: EXT-5 (the adaptive-envelope objection and the missing test), EXT-4 (the learned-blind threshold check).
- **AM-54** — **The classical baseline was tuned by a classifier the project then replaced.** Changed: `params.reference_classifier.br4_selection_passes`, `br4_selection_terminates_after_pass` and `headline_scorer` added; BR-4 runs two passes and stops; BR-12 names which scorer carries the headline. Why: BR-4 selects codec and MCS configurations under BR-8's clean-trained classifier, which is the only one that exists at that point; BR-12 then fine-tunes on the artifacts *those selections* produce and rescores the results. The loop was never closed, so the reported classical arm sat at a configuration chosen by a scorer nobody reports — and because the artifact-finetuned classifier tolerates heavier compression it would plausibly prefer a different point, compressing harder and spending the savings on stronger channel coding. Reporting the baseline at the weaker scorer's choice understates it, which is the direction ER-8 and DEC-16's governing rule both prohibit, and it is the first thing an examiner asks once the two classifiers are described. Two passes closes it; terminating at two is preregistered so the loop cannot be iterated until it flatters a result; and the second pass is cheap because `params.baseline.j2k_cache_key` makes it classifier forward passes over already-emitted codestreams rather than a re-encode. Raised by: EXT-4 (the ambiguity), EXT-5 (the circularity), user (the two-pass decision).
- **AM-55** — **The H4 control was arithmetically infeasible at every operating point but one.** Changed: transmit_feature_dim removed from `params.digital_semantic_control.shared_with_learned` and from the conceptual allowlist; `transmit_dim_grid`, `transmit_dim_units`, `transmit_dim_realised_by`, `width_selection`, `selection_search`, `selection_search_is_cross_product` and `channel_interface_comprises` added; `entropy_table_bytes_counted` changed from true to false; ER-9 rewritten; §2's H4 language softened from causal attribution to consistency under the tested control; new G-11 gates W9. Why: sharing the transmitted feature dimension pinned ER-9 at 2k real values while the digital budget supplies only `Q_m × R / 2` bits per value — 1.67 at 16-QAM rate 5/6, 0.5 at QPSK rate 1/2 and **0.167 at BPSK rate 1/3**, against a 2-bit floor in the quantiser grid. Every configuration except 16-QAM at rate 5/6 was impossible, and that one decodes only above roughly 11 dB, entirely outside H1's region — so the control would have been at outage and scored at chance across exactly the range H4 is tested in, making H4 unfalsifiable, trivially easy to support, and the primary novelty claim of DEC-13 a system broken by construction. That is the AM-15 failure class at larger scale. The fix keeps the encoder architecture identical and lets ER-9 choose its own transmitted dimension, because deciding how many values to send against how precisely to send each one **is** the digital channel interface — an analog system makes no such choice — so it remains a difference in `differs_only_in` rather than an addition to it. The search is two-stage rather than a cross product so W9's training count stays bounded. Feasibility is now verified rather than assumed: `spec/evidence/check_packetisation.py` asserts a feasible pair exists at every live configuration, and at the tightest — STL-10 at the low ratio, BPSK rate 1/3, 94 payload bytes — seven pairs fit. The entropy table stops being charged per image because it is fitted offline and installs with the model exactly like network weights, quantiser scales, JPEG 2000 coding rules and LDPC matrices, none of which are charged; charging it weakened the control on every image, again in the direction that makes H4 easier. G-11 exists because W9 builds this entire system, plus ER-2, in one week with no gate on it, while §16 already warns ER-9 must not be the first thing cut.
