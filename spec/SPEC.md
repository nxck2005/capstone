**Status:** normative, hand-maintained. This file is the single source of truth for the project.
`DATASHEET.md`, `concerns/*.md` and `params.generated.yaml` are **generated from this file** — never edit those by hand.

**Keywords.** MUST, MUST NOT, SHOULD, SHOULD NOT and MAY are used in the RFC-2119 sense. A MUST that cannot be met is a spec change, not a quiet exception.

**Requirement IDs.** `SR` system · `BR` baseline · `ER` experiment · `DR` demo · `HR` hardware · `PR` programme deliverable · `OPT` optional/non-blocking · `FW` future work · `DEC` settled decision · `G` schedule gate · `AM` amendment. IDs are permanent: retire, never renumber. A retired ID is struck through in place and keeps its number reserved (§14).

**Amendments.** Any change to a requirement, decision, parameter or gate after this file first acquired that text is recorded as an `AM` entry in §17 stating what changed and why, and the amended item carries an `(AM-n)` back-reference. Nothing is edited silently. Rationale: this document is read by examiners and by external reviewers who did not see the previous version, and a spec that changes without a record cannot be distinguished from one that changed *because* of what the author later wanted it to say.

## 1. Purpose & thesis

Standard wireless practice compresses a source and separately protects the bits against noise, then rebuilds the file bit-for-bit at the receiver — an architecture optimised for pixel-perfect reconstruction. This project instead trains a neural **encoder** (sender) and **decoder** (receiver) end-to-end through a differentiable channel model, so that only what the downstream task needs survives the link.

The claim is structural, not a tuning result:

1. The **task-agnostic image-reconstruction baseline of record** — a standard source codec plus a standard channel code — has no representation of what the bits are *for*; its objective is fidelity, and task success is not expressible in it. This is a statement about *that* pipeline, not about digital systems in general: a digital transmitter could send quantised task features, logits or labels instead of an image. ER-9 builds exactly such a system as a control, so the thesis is tested rather than assumed.
2. Shannon's separation theorem makes compress-then-protect optimal only in the limit of infinitely long messages. Real edge/IoT links send **short** messages over **noisy** channels — a regime where separation is known to incur finite-blocklength and delay penalties, and where joint source-channel coding *may* therefore gain (Kostina & Verdú, arXiv:1209.1317). That is the hypothesis under test, not a theorem being applied.
3. The observable signature is **graceful degradation**: separated coding has a cliff below which the receiver gets nothing, while the learned system degrades continuously — blurrier, still task-correct.

Because a single learned-vs-classical gap conflates two distinct advantages — **task-aware representation** versus **joint coding** — the comparison of record is a three-way one: classical reconstruction pipeline, task-aware *digital* pipeline (ER-9), and learned JSCC. ER-4 and ER-9 together decompose the gap; without them the result cannot be attributed.

Two further claims are **not** made. The systems are compared at equal channel uses and equal average symbol power, which is equal transmitted energy under the stated model: the result is better accuracy at equal resources, **not** a measured energy saving. And no claim is made about beating published DJSCC results (§13).

The Tier 1 deliverable is this effect demonstrated, quantified and *attributed* on a simulated channel, against a baseline tuned in the baseline's own favour.

## 2. Success criterion and preregistered hypotheses

Completion and outcome are deliberately separated. A capstone commits to a defensible process, not to a favourable measurement.

**Tier 1 is complete** when both systems (and the ER-9 control) are implemented, validated (G-1, G-2, G-7), bandwidth-matched (BR-3), fully bit-accounted (BR-10, BR-11), evaluated at the operating point selected by the learned-blind rule in ER-3 (G-8), and reported with paired inference (ER-10) under this preregistered protocol. **Completion does not depend on which way the result falls.**

**The hypotheses**, each decided by the paired procedure in ER-10 and each reported either way:

- **H1 — low-SNR separation (primary).** Supported if the paired 95% interval for (learned − classical) top-1 accuracy lies strictly above zero at **three or more consecutive** SNR grid points at or below `params.channel.train_snr_db_fixed`. Consecutiveness is a preregistered run rule, not three independent tests; no per-point significance is claimed, and the rule is **stricter** than a single-point test rather than looser — see the family-wise error note below. Reported alongside it and preregistered as the effect size of record: `params.evaluation.h1_effect_size`, the mean paired accuracy difference over the whole region at or below `params.channel.train_snr_db_fixed`, with a `params.evaluation.ci` interval. The run rule decides H1; the scalar states how large the effect was, which a yes/no rule cannot (AM-3).
- **H2 — graceful versus cliff.** The comparison window is selected **on the validation split** and then frozen (DEC-12): among all pairs of grid points exactly `params.evaluation.cliff_window_db` dB apart, take the pair over which the **classical** system loses the most top-1 accuracy. On the test split both systems are then evaluated over exactly those endpoints. Supported if the classical system loses at least `params.evaluation.cliff_drop_pp` percentage points there while the learned system loses no more than `params.evaluation.graceful_drop_pp`. Rationale: the cliff is a property of the classical system, so the classical curve is what defines the window; selecting it on test would leave DEC-12's validation-only rule with exactly one hole; and because `params.channel.test_snr_grid_db` is irregularly spaced, "a 4 dB window" is well defined only as the set of endpoint pairs the grid actually admits, which code derives from the grid rather than reading from a hard-coded list (AM-1).
- **H3 — convergence.** Supported if the paired accuracy gap trends toward zero as SNR rises: `params.evaluation.gap_trend_test` — the weighted least-squares slope of the paired gap against SNR over the full test grid — is negative with a `params.evaluation.ci` interval excluding zero. Deliberately *not* "monotone at every point": measured curves fluctuate, and one grid point moving the wrong way by a fraction of an interval width is noise rather than a refutation, so a monotonicity rule would have no executable pass condition (AM-2). A **crossover is reported if observed but is not required**: at low bandwidth ratios the learned system is expected to dominate at every SNR, which supports H1–H3 and is not a failure. DEC-16 states how the operating point and the baseline's modulation adaptivity are chosen to make a crossover observable if one exists, and what is reported if it does not.
- **H4 — attribution.** Joint coding is credited only to the extent the learned system also exceeds the ER-9 task-aware digital control under the H1 rule. If it does not, the gain is attributed to task-aware representation and reported as such.

**Family-wise error, recorded so it is not re-litigated.** H1's run rule is sometimes read as a multiple-comparisons problem — many candidate runs are examined, therefore the false-positive rate must be inflated. The arithmetic runs the other way. `params.channel.test_snr_grid_db` holds 13 points at or below `params.channel.train_snr_db_fixed`, so there are 11 candidate runs of three. Under the global null of no true difference anywhere, and with a one-sided per-point error of 0.025: if the points were independent the probability that any run of three all clears the interval is at most 11 × 0.025³ ≈ 1.7 × 10⁻⁴; if they were perfectly dependent it is 0.025. Both are stricter than the 0.05 a single point would carry, and real adjacent SNR points — same models, same images, neighbouring noise levels — are strongly positively dependent, so the realised rate lies between those bounds. **Requiring a run is the multiplicity control, not a defect in it.** The cost is power rather than validity, which is the direction a preregistered primary hypothesis should err in (AM-4).

**Outcome reporting.** Any combination of supported and unsupported hypotheses is a valid, complete Tier 1. ER-8 governs: a negative or partial result is reported with the same rigour as a positive one, and weakening the baseline to manufacture a result is prohibited.

## 3. Settled decisions

- **DEC-1** — **Dataset ladder.** The headline result targets Imagenette at 160px, with STL-10 at 96px as the sole fallback headline, invoked at G-8 if compute or a degenerate baseline forces it. **CIFAR-10 is a plumbing smoke path only** — shape checks, gradient flow, kill-and-resume, schema — and MUST NOT become a headline dataset: at every ratio in `params.bandwidth.ratios` its channel budget is below the floor of any real image container (BR-11), so its classical baseline is pinned at chance for a file-format reason and no comparison made on it means anything. Dataset MUST be a configuration axis, never a code fork. Rationale: highest-resolution headline the hardware can carry, with one pre-agreed step-down, and no fallback that leads off a cliff.
- **DEC-2** — **Dual-head decoder.** One decoder carrying a reconstruction head and a classification head, trained with `loss = CE + λ·MSE`. Rationale: the accuracy curve and the "blurry but still task-correct" demo visual come from one model rather than two, at a measured accuracy cost (SR-9). Reversal ladder, cheapest first: (a) relax the reconstruction floor to `params.learned_system.lambda_psnr_floor_relaxed_db`, since §13 already makes reconstruction quality a non-goal; only if that also fails, (b) split into two models and record the change here. (b) roughly doubles the training budget and MUST NOT be taken after G-4 without re-planning the schedule.
- **DEC-3** — **Python primary.** Learned system and classical baseline are both Python; MATLAB appears only as non-blocking cross-checks (OPT-1..OPT-3). Rationale: one language, one CI path, no license dependency on the critical path.
- **DEC-4** — **Compute.** An RTX 4060 Mobile (8 GB) is the assumed trainer, with Colab/Kaggle free tier as overflow. University cluster access MUST NOT appear on any critical path. Consequence: checkpoint/resume (SR-10) and a measured compute budget (SR-11, G-7) are hard requirements, not conveniences.
- **DEC-5** — **Radio hardware deferred.** Tiers 2 and 3 are specified as capability requirements plus a budget range (HR-1), not a named device, and no purchase happens before G-5.
- **DEC-6** — **Required experiments.** Operating-point selection, core comparison, SNR-mismatch robustness, the task-training ablation, the task-aware digital control and the paired inference procedure are required (ER-1..ER-4, ER-9, ER-10). Rayleigh fading and the λ sweep are future work (FW-1, FW-2), but the extension points that admit them (SR-5, SR-8) are required now.
- **DEC-7** — **Demo styling.** The Streamlit demo and the thesis figures share one publication-grade plotting module (DR-4), so a demo screenshot is directly usable in the report.
- **DEC-8** — **Document structure.** This file is authoritative and self-sufficient: a reader who never runs the generator loses nothing. All other files under `spec/` are derived views.
- **DEC-9** — **Source codec.** The classical baseline of record uses **JPEG 2000**, not JPEG. Rationale: JPEG carries an irreducible container floor of roughly 250–290 bytes (quantisation tables, frame and scan headers) even with optimised Huffman tables, which at these channel budgets is a large or total fraction of the payload — at the core ratio it consumes most of Imagenette's budget and all of CIFAR-10's, and on STL-10 it makes the low-rate LDPC configurations infeasible outright, so the low-SNR "cliff" would be a file-format artifact rather than a channel effect. JPEG 2000 has no comparable floor and its rate control is fine-grained enough to land close under any budget. **Correction, recorded rather than quietly dropped:** this decision originally claimed JPEG 2000 "supports exact target-byte rate control, which also collapses the quality sweep to a direct budget solve". It does not, at least not through the tooling this project will use — OpenJPEG's `opj_compress` exposes a per-layer compression *ratio* (`-r`) and a per-layer *PSNR* target (`-q`), which are mutually exclusive, and neither guarantees an exact emitted byte count. BR-1 therefore drives it as a cached search whose emitted size is authoritative (AM-8). This weakens the convenience argument but not the decision: the container-floor argument above is the load-bearing one, and a `≤ budget` guarantee is all BR-3's equal-channel-uses claim ever needed. JPEG is retained as a **secondary reported curve** (`params.baseline.source_codec_secondary`) because it is what practitioners actually deploy, and BR-11 makes the overhead difference visible rather than hidden.
- **DEC-10** — **LDPC provenance.** **Sionna `2.0.1`** provides base-graph and lifting-size selection, encoding, rate matching and decoding; everything in `params.baseline.ldpc_impl_local` is implemented in this project, behind the adapter seam required by BR-14. Reasoning, recorded so it is not re-litigated: (a) Sionna 2.0.0 migrated PHY and SYS to PyTorch and no longer depends on TensorFlow, so the "second deep-learning framework" objection this decision originally carried was checked against the release notes and is **obsolete** — the environment stays single-framework and DEC-3 is satisfied; (b) the classical baseline is never trained, so the codec need not be differentiable, which makes correctness and throughput the only real criteria; (c) Sionna implements TS 38.212 rate matching, which is the genuinely error-prone part, but **not code-block segmentation**, which is why the local layer exists and is where the standards work for PR-3 actually lives; (d) `params.baseline.ldpc_decoder` is a Sionna built-in check-node update, so no custom callable and no scaling factor to justify. Rejected: implementing the whole chain locally — roughly a week landing at W3 with no slack, gating G-2 which gates everything, and a silent base-graph transcription error is the worst failure mode available; AFF3CT via `py_aff3ct` — a C++ build on WSL2, CPU-only marshalling per codeword, and a second toolchain on the critical path, which is now the only remaining DEC-3 violation among the candidates. **Note the scope of that rejection:** it rules AFF3CT out as the *runtime* implementation, not as a one-shot generator of BR-2's golden vectors. A fixture generator runs once, emits a committed `.npz`, and never appears in CI or at runtime, so none of the objections above apply to it and DEC-3 is untouched — which is why it sits on `params.baseline.ldpc_golden_vector_source_ladder` despite being rejected here (AM-22). Also rejected: generic Python LDPC packages (`pyldpc`, ProtographLDPC) — Gallager/protograph codes rather than 5G NR, so they cannot satisfy G-2 or PR-3 at all; pyAerial — needs the Aerial SDK and a datacenter GPU. Fallback ladder: pin an earlier Sionna if 2.0.x proves unsound at G-2, then drop to `params.baseline.ldpc_impl_fallback` behind the BR-14 seam with the segmentation layer already written and tested. The version pin, golden-vector provenance and measured throughput are recorded at G-9.
- **DEC-11** — **Training-SNR protocol.** One model is trained **at `params.channel.train_snr_db_fixed`** for each ratio ER-3 names — `params.bandwidth.crossover_ratio`, `params.bandwidth.efficiency_ratio` and `params.bandwidth.low_ratio_operating_point`, at most three and two if the first two coincide — and evaluated across the whole test grid. Not one model per test SNR, not one per entry in `params.bandwidth.ratios`, and not SNR-randomised training — the last becomes OPT-4. Rationale: fixed-SNR training is what makes ER-2's mismatch profile meaningful, and it bounds the training count at one run per selected ratio per seed. This originally read "per bandwidth ratio", which implied a learned model at all five ratios; ER-3's selection rule is learned-blind by construction, so those extra runs could not have informed the decision they appeared to serve (AM-12).
- **DEC-12** — **Selection uses validation data only.** Every choice that could flatter a result — baseline codec quality and LDPC rate (BR-4), λ (SR-9), training checkpoint, operating ratio (ER-3), architecture — MUST be made on `params.datasets.*.val_images`, disjoint from the test split. The test split is touched once, for the frozen configuration. Rationale: `best config per test SNR` selected on test labels is test-set leakage and would invalidate every interval in §2.
- **DEC-13** — **Novelty position.** The course rubric scores novelty, while §15 disclaims beating published DJSCC results. These are reconciled by naming the contribution as one thing rather than two loose ones: **a reproducible, matched-channel-use comparison of image-digital, task-feature-digital and learned-JSCC transmission, with complete container and physical-layer bit accounting, evaluated under one common task protocol.** Its two load-bearing components remain (a) the ER-9 attribution decomposition separating task-aware representation from joint coding, and (b) the BR-11 format-overhead-controlled classical baseline. Reproduction quality carries the results marks; the decomposition and the accounting carry the novelty marks. **What is deliberately not claimed:** neither graceful degradation nor cliff-avoidance is novel — both are core findings of the earliest DeepJSCC work — and task-aware digital semantic systems, quantised semantic features and separate task-oriented source/channel schemes all have substantial prior art. The claim is the controlled three-way comparison and its accounting, not the existence of any one of the three systems. Claim (b)'s "which the DJSCC literature does not report" is **conditional on PR-1**: it is an assertion about the literature and MUST be verified by the completed review before it appears in the report, not asserted in advance from this file (AM-10). PR-7 makes this an explicit written deliverable rather than a viva improvisation.
- **DEC-14** — **Tiers 2 and 3 are stretch goals.** The expected and planned demonstration is **pre-recorded**; a live SDR replay or RPi demo is upside, not the baseline plan. Rationale: procurement lead time plus IQ framing, synchronisation, frequency offset and calibration (HR-6) is a second project, and HR-5 already makes Tier 1 standalone. Framing them as expected deliverables converts likely upside into apparent shortfall.
- **DEC-15** — **Pretrained weights prohibited for the reference classifier.** `params.reference_classifier` MUST be trained from scratch. Rationale: Imagenette is a subset of ImageNet, so ImageNet-pretrained weights are label leakage an examiner will spot immediately. `clean_acc_floor` values are set to from-scratch reality accordingly.
- **DEC-16** — **Crossover strategy, and its last-resort fallback.** A crossover requires the classical system's high-SNR ceiling to exceed the learned system's, which the original parameters made arithmetically impossible — the baseline was capped at QPSK, so its payload could not grow no matter how clean the link became, and both curves flattened into parallel lines (worked through in `docs/crossover-explained.md`). The remedy is to **remove an artificial cap on the baseline, never to weaken the learned system**: `params.baseline.modulations` gains 16-QAM and `params.baseline.modulation_tuning` makes modulation an adaptive axis of BR-4's per-SNR tuning, so the baseline transmits more per channel use as conditions improve, exactly as deployed systems do. Because BR-4 reports the best feasible configuration at each SNR, this strictly raises the classical curve at high SNR and cannot lower it at low SNR, so the cliff that H2 depends on is untouched. Governing rule: every lever used to obtain a crossover MUST either strengthen the baseline or be preregistered; handicapping the learned system to manufacture one is prohibited and would violate ER-8. **Fallback, last resort only:** if the adaptive baseline still does not cross by G-8, the project reports learned dominance across the whole grid, promotes the reconstruction-quality crossover to the secondary figure, and relies on §2, which already makes that a complete Tier 1. This fallback exists to keep the demo and the thesis intact, not as a preferred outcome; taking it MUST be recorded here together with the G-8 evidence that the adaptive baseline was genuinely attempted first. **Supervisor position, recorded 2026-07-25:** pursue a crossover as hard as the rules allow, and fall back to reporting dominance across the grid if it genuinely does not appear. That is this decision's existing structure, now externally ratified rather than self-declared, and it converts the fallback from an author's convenience into an agreed outcome (AM-19). **It does not relax the governing rule and MUST NOT be cited as if it did.** "Try hard for a crossover" authorises strengthening the baseline and preregistering levers; it authorises nothing on the learned system's side of the comparison. Weakening the learned model, truncating the SNR grid before 16-QAM decodes, selecting the operating ratio on anything but ER-3's learned-blind rule, or reporting a fixed-modulation classical curve as the headline all remain prohibited under ER-8, and a crossover obtained by any of them would be worth less than no crossover at all.

## 6. Baseline requirements (BR)

The baseline exists to be beaten honestly. Every requirement here is a defence against an unfair comparison.

- **BR-1** — The classical chain MUST be `params.baseline.source_codec` → `params.baseline.channel_code` → modulation → the same channel implementation the learned system uses. The codec MUST emit `params.baseline.j2k_container` and MUST be driven per `params.baseline.j2k_rate_control` via `params.baseline.j2k_rate_control_method`: the encoder is asked for a compression ratio, the emitted file is measured, and per `params.baseline.j2k_emitted_size_authoritative` **that measured size — not the requested ratio — is what counts against the budget**. The requirement is a codestream that does not exceed the payload budget, never one that exactly equals it; residual slack MUST be carried as filler and reported, not discarded (AM-8). `params.baseline.source_codec_secondary` MUST be reported as a labelled second curve, not substituted for the first (DEC-9), and it is sufficient to report it at `params.bandwidth.core_ratio` for one entry in `params.evaluation.train_seeds` — it is context for what practitioners deploy, not a hypothesis-bearing curve (AM-13). *(verify: integration test asserting the shared channel object; a test that every emitted codestream is ≤ its budget with the slack logged; and both codec curves present in the results CSV)*
- **BR-2** — The LDPC chain MUST be validated two ways before any learned-vs-classical comparison is reported. **Bit-exactly**: encoder output and rate-matched output MUST reproduce `params.baseline.ldpc_golden_vector_file`, a fixture generated from an implementation independent of `params.baseline.ldpc_impl` whose provenance is fixed at `params.baseline.ldpc_golden_vector_source_gate` by descending `params.baseline.ldpc_golden_vector_source_ladder` until one rung is confirmed available. The ladder exists because the MATLAB licence is being attempted but is **not assured** (AM-22), and BR-2 gates G-2 which gates every reported comparison, so a single-sourced fixture would put the whole comparison behind a licence decision the project does not control. Rung 2 is the load-bearing one: the srsRAN Project ships committed binary vectors covering all base graphs and lifting sizes, generated from MATLAB's 5G Toolbox as its own trusted reference — which yields MATLAB-provenance vectors without a MATLAB licence, and is independent of Sionna, which is all this requirement asks. Whichever rung is used, `params.baseline.ldpc_golden_vector_licence_check_required` means the source's licence MUST be checked before its vectors are committed to this repository, and the rung actually used MUST be recorded with the fixture. **Statistically**: measured BER/BLER MUST match published `params.baseline.ldpc_standard` curves **for every entry in `params.baseline.modulations` that BR-4 may select**, with every reference curve converted to this project's SNR convention using `params.channel.snr_conversion` and the conversion shown in the archived artifact. Higher-order modulations need soft-demapping to log-likelihood ratios rather than a sign decision, so an unvalidated 16-QAM demapper would silently degrade the baseline — the opposite of BR-4's intent and a direct threat to DEC-16. - **ER-1** — **Core comparison.** Learned, classical and ER-9 control systems, full test split, every SNR in `params.channel.test_snr_grid_db`, at `params.bandwidth.headline_ratio` — which resolves to `params.bandwidth.crossover_ratio`, because a crossover claimed from a one-seed sweep figure while the full-strength intervals sit at a different budget would rest the project's most contested result on its weakest evidence (AM-20) — repeated over the seed cells defined by `params.evaluation.seed_pairing` — `params.evaluation.train_seeds` **zipped with** `params.evaluation.channel_seeds`, giving three cells, not their nine-cell cross product — reported with `params.evaluation.ci` intervals, measuring `params.project.primary_metric`. - **ER-3** — **Operating-point selection and bandwidth sweep.** Before the headline run, sweep every entry in `params.bandwidth.ratios` **with the classical system only**, on the **full validation split** at one seed, and select **two** operating points at G-8 by this preregistered, **learned-blind** rule applied at two thresholds: *the smallest ratio at which the classical system's high-SNR ceiling comes within `t` percentage points of its clean-image accuracy*, evaluated at `t` = `params.bandwidth.efficiency_ratio_threshold_pp` to give `params.bandwidth.efficiency_ratio`, and at `t` = `params.bandwidth.crossover_ratio_threshold_pp` to give `params.bandwidth.crossover_ratio`. Both are lookups against the same classical sweep table, so the second threshold costs nothing to evaluate, and the two MAY select the same ratio — in which case there is one operating point and `params.bandwidth.headline_ratio` resolves to it unchanged. Rationale for two: the looser threshold locates the **efficiency point**, the tightest budget at which the baseline is still healthy, which is where the bandwidth claim lives; but "within 5 points of clean" admits a classical ceiling around 0.83 while the learned ceiling is estimated at 0.85–0.87, so that threshold can select a ratio at which no crossover exists at all. The tighter threshold locates the **crossover point**, the smallest budget at which the classical ceiling can actually overtake the learned one. Reporting both shows the trade-off as a function of budget rather than asserting it at a point (AM-20). The rule inspects only the classical system at either threshold, so it cannot be accused of selecting for the hypothesis; it places the comparison where the baseline is healthy rather than where it is starved, and tightening a threshold hands the baseline *more* budget, which DEC-16's governing rule expressly permits. Because BR-4 now adapts modulation as well (DEC-16), the classical ceiling rises faster with SNR than it would under a fixed modulation, so the rule is expected to select a *smaller* ratio than it otherwise would — the crossover is bought with better use of the budget rather than with more budget. The sweep also reports `params.bandwidth.low_ratio_operating_point` as the bandwidth-starved regime where dominance rather than crossover is expected. Because the rule is learned-blind, learned systems MUST be trained at `params.bandwidth.crossover_ratio`, `params.bandwidth.efficiency_ratio` and `params.bandwidth.low_ratio_operating_point` **only** — at most three ratios, and two if the thresholds coincide — nothing in §2 needs a learned model at every ratio, and training five would spend roughly nine runs to inform a decision that cannot see them (AM-12). The sweep uses the full validation split rather than `params.evaluation.test_subset_size`: that parameter sizes a subset of the *test* split under ER-6, and at 2000 it exceeds the `val_images` count of every dataset in `params.datasets`, so the requirement as previously written could not be executed at all (AM-14). *(verify: results CSV + figure, an archived record of the rule's evaluation at every ratio, and an assertion that no learned-system row exists at a ratio outside the two named here)*
- **ER-4** — **Task-training ablation.** The semantic reconstruction head MUST also be scored through the frozen `params.reference_classifier` (BR-8), separating gain attributable to joint coding from gain attributable to a task-trained classifier. - **ER-5** — Every experiment MUST emit rows matching `params.artifacts.csv_schema` exactly — same columns, same order — alongside the per-image file required by SR-18. *(verify: schema validation script over all result CSVs)*
- **ER-6** — Evaluation on `params.evaluation.test_subset_size` images is permitted for sweeps only; `params.evaluation.full_test_split_required_for` MUST use the full split, and the `test_subset` column MUST record which was used. *(verify: schema test asserting the flag)*
- **ER-7** — Every number appearing in the thesis MUST be traceable to a `run_id` and `git_commit` in a committed CSV. *(verify: audit script resolving each reported figure to its rows)*
- **ER-8** — If a hypothesis in §2 is unsupported, the negative result MUST be reported with the same rigour as a positive one, together with the diagnostic evidence. - **ER-9** — **Task-aware digital control.** A third system MUST be built and evaluated at matched `k`, sharing every element in `params.digital_semantic_control.shared_with_learned` with the learned JSCC system and differing from it **only** in `params.digital_semantic_control.differs_only_in`: features taken at `params.digital_semantic_control.transmit_layer` are quantised per `params.digital_semantic_control.quantiser` at a width selected from `params.digital_semantic_control.quantiser_bits_grid` on the validation split (DEC-12), entropy-coded per `params.digital_semantic_control.entropy_coder`, and carried over the same `params.baseline.channel_code` chain as the classical baseline with its transport configuration tuned per `params.digital_semantic_control.transport_tuning`. It MUST be scored by `params.digital_semantic_control.scored_by` — a task head architecturally identical to the learned system's — **not** by the frozen `params.reference_classifier`, which consumes images and cannot read a feature stream (AM-5). Matched `k` fixes the feature budget directly: transmitted feature count × quantiser width + entropy-coder and container overhead MUST fit the same `params.baseline.budget_rule` payload the classical baseline receives. Rationale: without a control that is task-aware *and* digital, the learned-versus-classical gap conflates task-aware representation with joint coding and §1 claim 2 cannot be attributed (H4); and unless the control shares the learned system's front end, a measured difference could equally be architecture, capacity or training objective rather than the channel interface. This is the primary novelty claim of DEC-13. *(verify: results CSV rows under a distinct `system` value at the same k as ER-1, plus an architecture-diff artifact showing that only `params.digital_semantic_control.differs_only_in` separates the two systems)*
- **ER-10** — **Paired inference.** The §2 hypotheses MUST be decided on **paired per-image outcomes** (SR-18), not on the overlap of two independent intervals: `params.evaluation.paired_test` for the point decision and `params.evaluation.ci` with `params.evaluation.bootstrap_resamples` for the interval on the accuracy *difference*, with the image-level bootstrap nested inside the seed hierarchy so `params.evaluation.train_seeds` and `params.evaluation.channel_seeds` contribute as separate variance components. Rationale: both systems see identical images and noise draws, so a paired test is both the natural and the far more powerful analysis — a three-seed Student-t interval has two degrees of freedom and would demand roughly a five-point gap to clear non-overlap. Three further rules make the seed hierarchy honest, since `params.evaluation.bootstrap_resamples` resamples images and cannot manufacture training-run evidence that three seeds do not contain (AM-11): the **classical arm has no training-seed dimension** — it is never trained — so the training-seed variance component belongs to the learned arm alone and a classical result MUST NOT be replicated across seed cells and counted as independent baseline runs; `params.evaluation.paired_test` MUST be computed **within** a seed cell and never pooled across cells, which would treat repeated measurements of the same images as independent; and each seed's accuracy-vs-SNR curve MUST be reported separately alongside the between-seed range, so the reader sees training-run spread rather than inferring it from an interval that mostly reflects image count. ER-10 also computes `params.evaluation.h1_effect_size` and `params.evaluation.gap_trend_test` for §2's H1 and H3. *(verify: inference script reproducing every reported interval from the per-image files, with a unit test on synthetic data of known effect size, and a test that no pooled-across-seeds McNemar statistic is emitted)*

## 15. Non-goals

Explicitly out of scope. Listed so that scope creep is a visible spec change.

- Bit-exact or perceptually-optimal reconstruction as an objective in its own right — reconstruction exists to serve the task and the demo.
- Reinforcement learning of any kind. The system is trained end-to-end by supervised gradient descent.
- Multi-user, MIMO, relay or interference channels; a single point-to-point link is assumed.
- Video, audio or real-time streaming sources.
- On-device training or adaptation; edge nodes run frozen models.
- Adversarial robustness, security or privacy of the learned representation.
- Beating state-of-the-art DJSCC results. The comparison of record is against the classical baseline, not against the literature; the novelty claimed is the attribution decomposition and the overhead-controlled baseline (DEC-13, PR-7), not headline numbers.
- Energy measurement. The systems are matched on channel uses and average power, which is equal transmitted energy by construction; no power-meter claim is made (§1).

## 17. Amendment record

What changed in this document after it first said something else, and why. Permanent and normative as history: `AM` IDs are retired in place, never renumbered or deleted (§8). Each entry names the items it touched, the defect that motivated the change, and who raised it — so a later reader can tell what an external review caught from what an internal audit caught, and so no settled question is re-litigated from scratch.

This section is append-only in one direction: an amendment that is itself later amended gets a **new** `AM` entry citing the old one, rather than an edit to the old entry.

**Amendment round 1 — 2026-07-25, pre-W0.** Sources: `EXT-3`, a full-specification review by ChatGPT returning a "commit but do not freeze" verdict; and `INT-1`, the internal audit run while adjudicating it. Roughly a third of `EXT-3` was adopted. Its central statistical objection (that H1's run rule has an inflated false-positive rate) was rejected on the arithmetic in AM-4, and three of its recommendations restated decisions already settled in DEC-10, DEC-14 and G-9. `INT-1` found five further defects, two of which — AM-14 and AM-15 — were more consequential than most of `EXT-3`.

- **AM-1** — **H2's comparison window was undefined.** Changed: §2 H2 now selects the window on the validation split, using the classical curve, over the endpoint pairs the grid admits at `params.evaluation.cliff_window_db`, then freezes those endpoints for the test evaluation; added `cliff_window_db` and `cliff_window_selection` to the evaluation parameters. Why: "the steepest 4 dB window of the grid" named neither the curve that defines steepness, nor the split it is chosen on, nor how an irregularly-spaced grid admits a 4 dB window at all — so H2 could have been settled after seeing test results, which is the one place DEC-12's validation-only selection rule had a hole. Raised by: EXT-3.
- **AM-2** — **H3 had no executable pass condition.** Changed: §2 H3 replaces "contracts monotonically (within interval width)" with a negative weighted-least-squares slope of the paired gap against SNR whose bootstrap interval excludes zero; added `gap_trend_test`. Why: strict monotonicity is refuted by any single point of measurement noise, and "within interval width" did not say how much deviation was tolerated, so H3 had no red/green answer and would have been argued rather than decided. Rejected alternative: EXT-3 proposed demoting H3 to exploratory, which discards a claim that costs one regression to state properly. Raised by: EXT-3 (diagnosis), INT-1 (remedy).
- **AM-3** — **H1 reported no effect size.** Changed: §2 H1 keeps the three-consecutive-point run rule as the decision procedure and adds `h1_effect_size`, the mean paired accuracy difference across the whole region at or below `params.channel.train_snr_db_fixed`, reported with a `params.evaluation.ci` interval. Why: the run rule answers whether there is separation but never how much, and a single preregistered scalar over a fixed region is both the number a reader wants and immune to any objection about run structure or window selection. Raised by: EXT-3 (as a replacement for H1; adopted as an addition instead, per AM-4).
- **AM-4** — **H1's run rule was defended rather than replaced.** Changed: §2 gains a family-wise error note stating the bound explicitly; H1's decision rule is unchanged. Why: EXT-3 argued the rule scans 11 candidate runs and therefore inflates the false-positive rate, and recommended replacing it with a simultaneous bootstrap band or a single scalar. The arithmetic is the reverse — under the global null the probability that any run of three clears a one-sided 0.025 interval is at most 11 × 0.025³ ≈ 1.7 × 10⁻⁴ under independence and 0.025 under perfect dependence, both stricter than a single-point test — so requiring a run *is* the multiplicity control and replacing it would loosen the primary hypothesis, not tighten it. EXT-3 also described the grid as 16 points; it holds 18, of which 13 are in H1's region. Recorded here because this objection is likely to recur. Raised by: EXT-3 (rejected), INT-1 (arithmetic).
- **AM-5** — **ER-9 could not be evaluated as specified.** Changed: ER-9 rewritten to share `params.digital_semantic_control.shared_with_learned` with the learned system and differ only in the channel interface, scored by its own task head; `digital_semantic_control` added to the parameters; `digital_semantic_control` removed from `params.reference_classifier.shared_by` and from BR-8.
