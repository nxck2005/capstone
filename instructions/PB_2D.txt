# 4. Critical semantic boundary: Imagenette classifier versus CIFAR smoke

The adjudicated frozen G-1 checkpoint is an **Imagenette-160 classifier**.

CIFAR-10 also has ten numeric class indices, but the ten indices represent a different class vocabulary. Equal output dimension does not make the labels semantically compatible.

Therefore:

* The real frozen classifier may score only Imagenette-160 canonical images and reconstructions.
* The frozen outage class used for real W4 task records must be selected from the Imagenette-160 validation labels.
* The complete real schema-conformant task records committed by PB_2 must be Imagenette-160 validation records.
* CIFAR-10 remains a transport, verdict, accounting, cache, and schema-plumbing smoke only.
* Do not report CIFAR `top1_acc`, `correct`, outage-class accuracy, or classifier predictions obtained from the Imagenette classifier.
* Do not reinterpret CIFAR class index `i` as Imagenette class index `i`.
* Do not train or introduce a CIFAR classifier in PB_2.
* Do not invent a second frozen classifier.
* Synthetic unit-test classifiers may be used only in tests and must be labelled fixtures.

Run the real CIFAR smoke separately from the task-scored record artifact. Its summary must state:

```text
transport-only plumbing smoke
no task accuracy
no frozen-classifier inference
not comparable to Imagenette task labels
```

Use the working 32 px CIFAR axis explicitly so the known 24/16 px JPEG-2000 configuration conflict does not contaminate the ordinary smoke. Retain a separate test reproducing that conflict.

If any current instruction is interpreted as requiring real CIFAR task accuracy through the Imagenette checkpoint, do not comply silently. Record:

# B2.1 — Implement and freeze the outage policy

Create:


## 5.1 Selection source

Select the constant class from the **entire committed Imagenette-160 validation manifest**, not from:

* a sample subset;
* loader order;
* decoded images;
* classifier predictions;
* test labels;
* assumed class balance;
* `1 / n_classes`.

This is a label-frequency calculation. It should not require image decode or classifier inference.

For every class index, count validation labels.

Select:

1. the highest validation-count class;
2. the lowest class index if multiple classes tie.

Measured outage accuracy is exactly:

```text
selected_validation_count / total_validation_count
```

Do not replace it with a theoretical value, even if it happens to equal `0.1`.

## 5.2 Selection artifact

The artifact must include at least:

```text

status

dataset_version

tie_break

selected_count
measured_validation_accuracy

denominator

selection_source_commit
generated_at
test_split_access
```

Required labels:

```text
bounded validation/plumbing integration
not the BR-4 full validation sweep
not a G-8 operating-point selection
not test evidence
```

The artifact must be deterministic apart from explicitly recorded timestamp fields.

## 5.3 Runtime policy

Provide a clean interface that:

* loads and verifies the frozen artifact;
* rejects a different dataset, manifest hash, class count, or policy;
* returns the same constant prediction for every outage row;
* never reselects the class during inference;
* never reads validation or test labels during ordinary prediction.

The primary outage outcome stays binary per image:

```text
correct = pred_label == true_label
```

Never assign fractional correctness to one row.

## 5.4 Sensitivity policy

Implement:

```text
keyed_uniform_random_label
```

using the existing central RNG utility:

```python
keyed_generator(
    "outage_label",
    {
        "split_manifest_hash": ...,
        "stable_sample_id": ...,
        "channel_seed": ...,
    },
)
```

The purpose is supplied as the first argument. Do not also place a `purpose` field in the identity if the central exact-key contract rejects it.

Generate one integer in:

```text
[0, n_classes)
```

The sensitivity prediction must be invariant to:

* row order;
* batch size;
* system control flow;
* how many other rows outage;
* intervening random draws.

It must vary when a declared identity component changes.

## 5.5 Required tests

At minimum:

* full validation counts reproduce the artifact;
* selected class is the true maximum;
* ties select the lowest class index;
* measured accuracy is count-derived, not `1/n`;
* selection uses validation rows only;
* test rows are rejected;
* runtime prediction does not reload or reselect;
* artifact dataset and manifest mismatches fail closed;
* sensitivity exact-key validation;
* sensitivity row-order and batching invariance;
* changing stable ID, manifest hash, or channel seed changes the keyed stream;
* constant fallback is invariant across systems.

## 6.4 Prediction semantics

For an Imagenette row:

### Delivered

* Run the exact frozen G-1 classifier on `reconstruction_input(decoded_image)`.
* Use evaluation mode and no gradients.
* `pred_label = argmax(logits)`.
* `outage = false`.
* `outage_reason` uses the repository’s canonical non-outage representation.
* `correct = pred_label == true_label`.
* Compute reconstruction metrics against the same canonical source pixels.

### Structural infeasibility

* Apply the frozen constant outage prediction.
* `outage = true`.
* `outage_reason = structural_infeasibility`.

### Codec infeasibility

* Apply the frozen constant outage prediction.
* `outage = true`.
* `outage_reason = codec_infeasibility`.

### Decode failure

* Apply the frozen constant outage prediction.
* `outage = true`.
* `outage_reason = decode_failure`.

Do not run classifier inference on missing reconstructions.

Do not invent substitute pixels for an outage.

# 12. Emergency usage-exhaustion protocol

When usage appears low, do not start:

* the full test suite;
* the bounded Imagenette run;
* a multi-file refactor;
* a new mutation group;
* a final documentation rewrite.

Perform these actions in order:

1. Stop beginning new work.

2. Safely finish or interrupt the current command.

3. Run:

   ```bash
   git status --short
   git diff --stat
   ```

4. Update `instructions/RESUME.md` with:

   * current B2.x row = `in-progress`;
   * exact files changed;
   * commands completed;
   * commands not run;
   * known passing tests;
   * known failing tests;
   * evidence rows already durable;
   * partial-run completion count;
   * exact next command;
   * whether the worktree is currently green.

5. Ensure partial evidence says:

   ```text
   complete: false
   ```

6. Commit coherent unfinished work:

   ```text
   wip(pb2): preserve <precise unfinished work>
   ```

7. Push.

8. Confirm:

   ```bash
   git rev-parse HEAD
   git rev-parse origin/main
   git ls-remote origin refs/heads/main
   ```

9. Report the pushed checkpoint SHA and stop.

A non-green pushed WIP commit is preferable to lost work, provided its failures are documented.

Never leave a dirty, unpushed worktree as the only resumption mechanism.

Never spend the final available usage polishing a chat report before pushing the ledger and work.

Emergency completion line:

```text
PB_2 INCOMPLETE — RESUME AT B2.<n>
```

If a durable push fails:

```text
PB_2 HOLD — DURABLE PUSH FAILED: <precise condition>
```
