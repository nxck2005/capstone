## 1. Objective

Implement the complete **read, validate, classify, recover, resume-plan and
merge-validation layer** that B4 and G8_C will use.

B3 must make these statements mechanically true:

1. A restart derives the exact remaining work from authenticated
   required-work-unit authority and validated per-unit state, never from
   filesystem order, completion order, timestamps, worker names or
   process-local memory.
2. A complete result is accepted only when its request file, result file, unit
   state, campaign bindings, B1C tooling contract, B2C state contract, schemas,
   identities, hashes, counts, execution class, attempt and shard provenance
   form one exact chain.
3. A hard exit at any point leaves either an already authoritative complete
   unit, an explicitly recoverable request/result publication, or a unit that
   restarts from trial zero on the same frozen seeds.
4. No incomplete, failed, bounded-smoke, malformed, duplicated, aliased,
   unregistered or merely present result contributes required BLER coverage.
5. Resharding changes membership only. It never changes seeds, request identity
   or an already completed result.
6. B3 creates no runner, performs no simulation, starts no smoke and produces
   no scientific BLER measurement or aggregate BLER table.

Green B3 means exact resume and merge validation are frozen, independently
verified, registered and mutation-tested, and that bounded B4 smoke may begin.
It does **not** mean a BLER runner exists or that any characterization has
occurred.

## 8. Canonical runtime layout

Physical runtime root is caller supplied; its production default is
`results/baseline/g8/work_units`. The logical repository-relative prefix is
fixed as `results/baseline/g8/work_units`.

For exact `work_unit_id`:

    digest = sha256(work_unit_id.encode("utf-8")).hexdigest()
    bucket = digest[:2]

Paths:

    <root>/<bucket>/<digest>.state.json
    <root>/<bucket>/<digest>.attempt-<attempt>.request.json
    <root>/<bucket>/<digest>.attempt-<attempt>.result.json

Rules:

* `attempt` is a positive base-10 integer with no sign, whitespace, prefix,
  suffix, decimal point or leading zero. `attempt-1` is valid; `attempt-01`,
  `attempt-0`, `attempt-+1` and `attempt-1.0` are invalid.
* Request and result files contain compact sorted-key canonical JSON:
  `ensure_ascii=true`, `allow_nan=false`, separators `(",", ":")`, no trailing
  newline. The SHA-256 is over the exact canonical file bytes.
* A result-linked state's `result_path` must equal the exact logical
  repository-relative path derived from its work-unit ID and attempt.
* No absolute path, `.`/`..`, alternate separator, normalization alias,
  symlink, hard-link alias, wrong bucket, uppercase digest or alternate
  extension is accepted.
* Authoritative state, request and result files must be regular files with link
  count one.
* Final request and result files are immutable once published. A retry writes a
  new attempt path and never overwrites a previous attempt.
* Temporary/staging names are never evidence.
* The scanner must never infer an attempt from lexical filename ordering.

## 9. Global reconciliation lock

    <root>/.reconciliation.lock

* Read/repair/reconcile/merge operations acquire it with
  `fcntl.flock(LOCK_EX)`.
* Future workers must acquire it with `fcntl.flock(LOCK_SH)` for the complete
  claim → request publication → execution → result publication → state-link
  transaction.
* Shared worker locks may coexist; exclusive reconciliation excludes every
  conforming worker.
* Per-unit B2C locks remain mandatory and are acquired inside the global
  shared/exclusive coordination boundary as appropriate.
* Release occurs on normal return, exception and process death.
* The lock file is infrastructure, not state or evidence.
* A symlink or dangling symlink at the lock path is rejected.
* There is no "continue without locking" fallback.
* Lock acquisition and release must be tested with real processes.

Single documented lock order, never reversed:

    global reconciliation lock  ->  per-unit B2C lock

work-unit ID to agree; require the attempt path to agree with the unit-state
attempt when the request is current; reject unknown fields, omitted fields,

    execution_class == "full_strength"
    trials_requested == 5000
    scientific_evidence == true
    merge_eligible == false
    test_split_access == 0
    label == "full_strength"

## 12. Result validation

For every result file: require canonical JSON bytes; locate and validate the
exact request for the same work unit and attempt; run
`validate_work_unit_result(result, request=request)`; require schema version 2;
require `request_sha256` to equal the exact request-file SHA; require exact
identity, SNR, packet IDs, seeds, tooling bindings and implementation binding;
require filename work-unit digest and embedded work-unit ID to agree; require
execution metadata `attempt` non-null and equal to the path/state attempt for a
production merge candidate; require execution metadata `shard_index` and
`shard_count` non-null and equal to the current state's shard assignment for a
production merge candidate; recompute all count-derived BER, BLER and Wilson
fields; reject any stored float that does not exactly reproduce from the
authoritative counts.

A production merge candidate must satisfy exactly:

    status == "complete"
    execution_class == "full_strength"
    trials_requested == 5000
    trials_completed == 5000
    scientific_evidence == true
    merge_eligible == true
    required_coverage_contribution == 1
    test_split_access == 0
    request_sha256 == exact request-file SHA-256

Also enforce:

    information_bits == trials_completed * K
    block_errors <= trials_completed
    bit_errors <= information_bits
    block_errors == 0 iff bit_errors == 0
    if block_errors > 0: block_errors <= bit_errors <= block_errors * K

`incomplete` and `failed` results are never merge candidates. A bounded-smoke
result is never required coverage even if an attacker changes its label,
filename, state or stored disposition flags.

## 13. Per-unit classification

Exactly one classification per required work unit, from a closed enum:

    absent
    claimed_unbound
    claimed_request_bound
    recoverable_request_binding
    recoverable_failed_result
    recoverable_complete_result
    failed_retryable
    completed_full_strength
    terminal_nonmergeable

Anything malformed or contradictory raises a typed HOLD exception and never
receives a benign classification.

* `absent` — no state, no attempt artifact. Resume: clean claim at attempt 1.
* `claimed_unbound` — state `claimed`, `request_sha256` null, no current-attempt
  request or result. Resume: clean claim at `old_attempt + 1`.
* `recoverable_request_binding` — state `claimed`, `request_sha256` null, one
  exact byte-canonical validating current-attempt request, no current-attempt
  result. Repair may bind the request SHA via B2C CAS. Read-only inspection
  never repairs automatically.
* `claimed_request_bound` — state `claimed`, `request_sha256` non-null, exact
  current-attempt request present and matching, no current-attempt result.
  Resume: restart at trial zero as a clean claim at `old_attempt + 1`.
* `recoverable_failed_result` — state `claimed`, request bound, one exact
  current-attempt `failed` result validating against the request. Repair may
  transition the current attempt `claimed -> failed`. Never contributes
  coverage.
* `recoverable_complete_result` — state `claimed`, request bound, one exact
  current-attempt complete result, fully valid chain. Repair may transition to
  `result_linked` without rerunning. In production mode the result must meet
  all full-strength merge conditions; in bounded-smoke inspection mode it
  remains nonmergeable.
* `failed_retryable` — state `failed`, any bound request matches, any
  current-attempt failed result validates, no complete result for that attempt.
  Resume: clean claim at `old_attempt + 1`.
* `completed_full_strength` — state `result_linked`; state, request, result
  path, request SHA, result SHA, attempt, shard metadata and complete result all
  validate; result is full-strength, complete, merge-eligible and contributes
  exactly one required identity. Terminal; excluded from every remaining-work
  list.
* `terminal_nonmergeable` — state `result_linked` with a valid chain whose
  result is bounded smoke or otherwise explicitly nonmergeable. Permitted only
  when the caller explicitly selects bounded-smoke inspection mode on an
  isolated nonproduction root. Production merge mode must HOLD, because a
  terminal nonmergeable state at a required production-unit location would
  permanently block the full-strength unit.

## 15. Historical-attempt rules

Attempts are append-only history. For one work unit: no artifact may exist for
an attempt greater than the state attempt; request/result paths for older
attempts may remain; an older result must validate against the older request; an
older complete merge-eligible result is forbidden if state advanced beyond it;
incomplete final result files are forbidden — the atomic resume policy discards
incomplete temporary output rather than publishing it as a final result; failed
older attempts contribute zero coverage; retries never overwrite earlier attempt
artifacts; retry number, attempt, shard number and execution order never enter
seed derivation; request bytes for the same full-strength work unit reproduce
identically across attempts; execution metadata may differ without moving
request or measurement identity.

## 16. Read-only inspection and explicit repair

`tools/inspect_g8_bler_resume.py` is read-only by default: authenticate all
contracts, acquire the exclusive reconciliation lock, census and validate the
root, produce a deterministic summary, make no filesystem or campaign-state
change.

Explicit repair requires `--repair-recoverable` and may perform only:

    claimed + exact unbound request        -> claimed with request_sha256 bound
    claimed + bound request + failed result -> failed
    claimed + bound request + complete result -> result_linked

Repair rules: hold the exclusive global reconciliation lock; acquire the exact
per-unit B2C lock; reread state, request and result after locking; recompute all
hashes and validations; use the current state SHA as B2C's expected predecessor;
perform only legal B2C transitions; reread and validate installed state; if
publication raises after the atomic replacement may have occurred, recover by
rereading authoritative bytes and never infer publication state from the
exception alone; never repair an absent state, malformed state,
failed-to-complete conflict, `result_linked` state or unknown file; never
create, rewrite or delete request/result files.

Repair must be idempotent: repeating it after success returns the same canonical
state and performs no additional transition.

## 17. Exact resume plan

Closed canonical resume-plan schema binding: B3 contract ID and externally
registered B3 contract SHA; B2C state contract ID and SHA; B1C tooling contract
ID and SHA; campaign ID; campaign-manifest SHA; required-identity SHA;

Rules:

1. Assigned order is the existing canonical shard-plan order.
2. Completed IDs are the exact assigned subsequence classified
   `completed_full_strength`.
3. Recoverable IDs are the exact assigned subsequence with one of the
   recoverable classifications.
4. Remaining IDs are the exact assigned subsequence not completed and not
   awaiting explicit repair.
5. After repair, a second scan must produce the exact updated plan.
6. `absent` proposes attempt 1.
7. A nonterminal state proposes exactly `old_attempt + 1`.
8. Attempt skips and regressions are impossible.
9. A retry is always a completely clean claim.
10. Resharding is allowed only on that next-attempt clean-claim transition.

15. A partial campaign is valid and reports missing IDs explicitly.

## 18. Merge validation

Merge **validation**, not a BLER table writer. The merge report must iterate in
exact complete required-artifact order; accept at most one validated
full-strength contribution per required work-unit ID; validate the complete
state/request/result chain; report validated completed IDs, missing IDs,
recoverable IDs separately and failed/nonterminal IDs separately; report
bounded-smoke contributions as zero; report unexpected artifacts as HOLD rather

only at `3213 / 3213`; never interpolate, extrapolate, round, synthesize,
default or reuse G2 evidence; never select an operating point; never construct a
`BlerTable`; never write a scientific result artifact in B3.

A complete merge report requires:

    3213 unique required IDs
    3213 validated result-linked states
    3213 exact full-strength requests
    3213 exact complete full-strength results
    3213 merge_eligible == true
    sum(required_coverage_contribution) == 3213
    no duplicates, no missing IDs, no unknown IDs
    test_split_access == 0 everywhere

For partial state, return an explicit partial report. Do not call it complete,
green, characterized or merge-ready.

## 19. Campaign-state reconciliation

Per-unit states and validated request/result chains are execution authority.
Campaign state is an atomically published summary.

Under the exclusive reconciliation lock: validate the live campaign state; scan
all 3213 required IDs; derive the exact canonical sorted list of
`completed_full_strength` IDs; compare it with
`campaign_state.identity.completed_work_unit_ids`.

Rules: campaign completed IDs may lag validated per-unit completions before
reconciliation, and may never lead them; a campaign-completed ID without
validated terminal full-strength evidence is a HOLD; reconciliation may add only
validated completed IDs and may never remove a completed ID;
`in_progress_work_unit_id` is not a shard-worker lease and is never resume
authority; during an offline reconciliation no worker is active because the
exclusive global lock is held; a stale non-null campaign
`in_progress_work_unit_id` may be cleared only when its corresponding per-unit
state is valid and nonterminal or completed and the operation preserves the
existing campaign transition rules; do not project bounded smoke, recoverable
results, failed attempts or claimed states into completed IDs; do not increment
validation, inference, training or test counters for BLER request/result
inspection or bounded smoke; campaign state publication must use the existing
atomic campaign-state writer; a read-only reconciliation function must be
available separately from an explicit apply operation. B3 closeout performs no
completion reconciliation because no unit exists.
