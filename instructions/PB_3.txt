## The analytic composition

    P(TB success) = product over code blocks of (1 - BLER_r)

    expected accuracy =
          P(TB success) × measured codec reconstruction accuracy
        + (1 - P(TB success)) × measured outage-class accuracy

Both inputs are **measured**, never assumed:

  * codec reconstruction accuracy comes from actual measured validation cells (the
    transparency-bitrate probe under `results/` is the precedent — it produced measured
    accuracy per byte budget and axis);
  * outage-class accuracy comes from PB_2's frozen constant-class selection, not from
    `1 / n_classes`.

Requirements:

  * BLER lookup is indexed by the **complete** required physical-layer identity. Per
    `baseline.ldpc_bler_reference_must_match` that is: k_and_n, base_graph, lifting_size,
    modulation, decoder_algorithm, decoder_offset, iterations, snr_convention. A lookup missing any
    of these is a defect.
  * No interpolation may silently extrapolate outside characterized support. Outside support, the
    lookup must raise or return an explicit "uncharacterized" verdict — never a quietly extrapolated
    number.
  * Candidate feasibility is cached (structural feasibility of a `(k, modulation, rate, axis)`
    candidate is expensive and deterministic).
  * Tie-breaking among equal-expected-accuracy candidates is deterministic and documented.
  * The three system modes must be representable: **adaptive** (`classical_adaptive`), **fixed
    modulation** (`classical_fixed_mod`), and **fixed MCS** (`classical_fixed_mcs`) — these are
    entries in `analysis.system_values`. `baseline.modulation_tuning` = `adaptive_per_snr` and
    `baseline.fixed_mcs_packet_count` = 1 are relevant.
  * Pass-one clean-classifier selection and the later pass-two artifact-finetuned selection must
    remain **separate code paths with separate state**. Per `reference_classifier.artifact_finetune_gate`
    the finetuned variant is gated at G-8 and must not be trained here.
  * **Two passes are the maximum.** Make this structurally enforced, not merely documented — a third
    pass must raise.

Checkpoint the composition work in the order the `RESUME.md` rows list it — each of these is a
self-contained capability with its own tests, and each is a safe stopping point:

>>> CHECKPOINT B3.1 — the composition arithmetic and its worked-example tests.
>>> CHECKPOINT B3.2 — the BLER lookup, its complete-identity requirement and the no-extrapolation
    guard.
>>> CHECKPOINT B3.3 — candidate feasibility caching and deterministic tie-breaking.
>>> CHECKPOINT B3.4 — the three system modes and the structurally enforced two-pass limit.

## Required tests

    analytic composition arithmetic (hand-checked worked examples, including the degenerate cases
      P=1 and P=0)
    product-over-code-blocks is correct for 1, 2 and many code blocks
    BLER lookup requires the complete physical-layer identity; a partial key raises
    no silent extrapolation outside characterized support
    candidate feasibility caching returns identical results to the uncached path
    selection tie-breaking is deterministic and matches the documented rule
    adaptive, fixed-modulation and fixed-MCS modes are each representable and distinct
    pass-one and pass-two selection state do not leak into each other
    a third selection pass raises
    no full sweep invocation (the budget guard refuses)
    measured — not assumed — codec accuracy and outage accuracy are the inputs

## Mutation tests this phase must catch

    more than two selection passes
    a wrong outage score substituted into the composition
    an incomplete BLER lookup key
    silent extrapolation beyond characterized support
    a full sweep launched without the G-8 flag

Commit after every two or three passing tests, recording coverage in the `RESUME.md` B3.6 row.
