# 4. C2.1 — Record two normative amendments

This repair includes two deliberate specification decisions.

Determine the latest committed `AM` number and append the next two sequential amendments. Do not
assume the number written below if the repository has moved.

Regenerate all generated specification views atomically.

## 4.1 Amendment A — resolve CIFAR-10 JPEG-2000 axes

Adopt this decision:

```text
params.baseline.downsample_axis_px.cifar10 = [32]
```

Remove 24 px and 16 px as configured CIFAR-10 JPEG-2000 axes.

Rationale to record:

* flat `j2k_resolutions = 6` requires a minimum 32 px tile dimension;
* OpenJPEG rejects 24 px and 16 px before rate control;
* these are invalid codec configurations, not useful low-rate candidates;
* CIFAR-10 is a plumbing smoke dataset;
* retaining only the native 32 px axis is simpler and less error-prone than introducing an
  axis-dependent wavelet-resolution rule;
* dynamic clamping would create a new codec rule and more cache-identity complexity without helping
  the headline dataset;
* the change prevents setup errors from entering the future BR-4 candidate table.

Update:

* normative parameters;
* BR-1 wording if needed;
* verification language;
* schedule/gate text;
* amendment ledger;
* generated YAML/views;
* documentation that currently calls the issue unresolved.

Verify that no live text still says the axis decision is open.

## 4.2 Amendment B — define BR-11 byte semantics exactly

Amend BR-11 and the relevant artifact semantics to define:

```text
bytes_sent = source_bytes = A / 8
```

This is the complete byte-aligned transport payload capacity placed on the channel.

For a successfully emitted raw JPEG-2000 codestream:

```text
header_bytes
```

means all structural codestream bytes:

* SOC;
* every main-header marker segment;
* every SOT marker segment;
* every tile-part header through and including SOD;
* EOC;
* equivalent structural bytes for every tile-part.

```text
payload_bytes
```

means all tile-part data bytes after SOD and before the next tile-part boundary.

Do not describe this more narrowly as pure entropy-coded sample data. JPEG-2000 tile-part data may
also contain packet-header information.

The required identity is:

```text
emitted_codestream_bytes = header_bytes + payload_bytes
```

Transport filler is:

```text
payload_filler_bytes =
    bytes_sent - emitted_codestream_bytes
```

and remains reported separately rather than folded into either BR-11 column.

Aggregate semantics:

* `header_bytes` and `payload_bytes` are means over all rows where a codestream was emitted;
* this includes both `delivered` and `decode_failure`;
* it excludes `structural_infeasibility` and `codec_infeasibility`, where no codestream exists;
* the fields are null only when the aggregate contains no emitted codestream.

Update the BR-11 verification language to require:

* a known-answer codestream parser test;
* a decode-failure-only aggregate retaining both byte columns;
* an archived overhead table;
* exact byte reconciliation.

# 7. C2.4 — Repair JPEG-2000 accounting and runner timing

## 7.1 Correct `Psot`

In a JPEG-2000 SOT marker segment, the layout is:

```text
SOT marker: 2 bytes
Lsot:       2 bytes
Isot:       2 bytes
Psot:       4 bytes
TPsot:      1 byte
TNsot:      1 byte
```

Therefore `Psot` begins six bytes after the beginning of the SOT marker:

```text
_PSOT_OFFSET = 6
```

Do not retain offset 4.

Validate:

* minimum SOT segment length;
* segment boundaries;
* `Psot` range;
* multi-tile-part behavior;
* `Psot = 0` last-tile fallback;
* EOC handling;
* exact total reconciliation.

## 7.2 Independent known-answer parser tests

Add a handcrafted raw codestream fixture containing:

* SOC;
* at least one ordinary marker segment;
* SOT with a known non-zero `Psot`;
* SOD;
* a known number of tile-part data bytes;
* EOC.

Assert exact known values for:

```text
header_bytes
payload_bytes
total bytes
```

Also add:

* a multi-tile-part fixture;
* a `Psot = 0` fixture;
* malformed/truncated segment tests;
* an actual OpenJPEG encode reconciliation.

Do not rely only on:

```text
header + payload == len(codestream)
```

because a wrong boundary can still satisfy that identity.

## 7.3 Aggregate all emitted codestreams

Aggregate BR-11 byte columns over every row with an emitted codestream:

```text
delivered
decode_failure
```

Do not restrict them to delivered rows.

For an all-decode-failure cell:

* `coverage_rate = 0`;
* PSNR/SSIM remain null;
* `header_bytes` remains populated;
* `payload_bytes` remains populated;
* PAPR remains populated;
* byte reconciliation remains exact.

For structural or codec infeasibility, these fields remain null when no codestream exists.

Update field-semantics denominators accordingly.

## 7.4 Preserve exact reconciliation

For every emitted codestream require:

```text
header_bytes + payload_bytes == emitted_codestream_bytes
```

and:

```text
header_bytes
+ payload_bytes
+ payload_filler_bytes
== bytes_sent
```

when the transport block exists.

Do not fold payload filler into the BR-11 `payload_bytes` column.

## 7.5 Complete row timing

The per-row timer must include the entire row path:

```text
source coding
transport
classifier inference when applicable
reconstruction metrics
outage scoring
record construction
```

Do not stop timing immediately after `run_classical_pipeline()`.

Use deterministic fake-clock tests or an instrumented scoring stub to prove classifier/scoring time
is included.

The aggregate `wall_clock_s` must be derived from all durable row timings, including rows completed
before a resume.

Do not report only the most recent resumed session's elapsed time as the total bounded-run time.

## 7.6 OpenJPEG preflight ordering

Validate the exact configured OpenJPEG version before creating:

* result directories;
* result artifacts;
* partial evidence files;
* J2K cache entries for this run.

Use the existing J2K environment/preflight implementation rather than creating a second version
parser.

Record the actual verified OpenJPEG version in the execution metadata.

Add a test that forces preflight failure and asserts no result directory or artifact is created.
