## Purpose

B1C is a narrow, pre-execution corrective checkpoint. B1 froze the broad BLER
measurement design, deterministic seed derivation, and work-unit request/result
schemas. A hostile line-by-line audit found three fail-open defects:

1. cached campaign/work-unit authority exposes mutable nested values, so a
   caller can corrupt the object later consulted by a builder or validator;
2. `bit_errors` and `block_errors` are constrained independently rather than
   as counts that can arise from the same decoded blocks; and
3. requests and results do not directly bind the frozen tooling-contract ID
   and SHA-256.

B1C also hardens execution metadata, live-state seed identity, produced-artifact
path containment, and independent-verifier completeness. No scientific result
exists and no conclusion changes. B1 remains a historical design checkpoint;
B1C is the corrective contract checkpoint that must be green before B2.

## C1 — immutable cached authority

No public reference used as scientific authority may be mutable. The preferred
representation caches canonical JSON bytes keyed by work-unit ID and parses a
fresh record for each lookup; fresh dictionaries are also required from
`campaign_bindings()`. A shallow `MappingProxyType` containing mutable nested
lists/dicts is not sufficient. Validators must obtain an independent
authoritative record rather than trusting a caller-mutated object.

Tests must prove that mutating returned campaign ID, manifest hash, nested
`identity["iterations"]`, nested `identity["k_and_n"]`, or appending/reordering
`source_packet_config_ids` cannot change a later request or validator; that
mutating an index result cannot change `required_work_unit()`; that corruption
cannot make an invalid request validate; and that a later valid request still
matches `required_bler_identities.json`.

## C2 — count semantics

Freeze these source definitions and generated-contract fields:

- one trial is one independently generated K-bit LDPC information block for
  the exact work-unit identity;
- the comparison domain is the complete K-bit information vector accepted by
  the encoder and returned by the decoder adapter, with `K = k_and_n[0]`;
- bit errors are the Hamming distance between transmitted and decoded K-bit
  vectors;
- a block error is exactly one when at least one of those K bits differs; and
- an encoder/decoder exception or malformed decoder output fails execution and
  is never completed characterized evidence.

For every result, including partial/incomplete results:

```text
block_errors == 0  iff  bit_errors == 0
block_errors <= bit_errors <= block_errors * K
trials_completed <= trials_requested
block_errors <= trials_completed
information_bits = trials_completed * K
bit_errors <= information_bits
```

Decoder failures are not extra block errors unless an actual K-bit decoded
vector was produced and compared. Reject zero-bit/nonzero-block, nonzero-bit/
zero-block, fewer than one bit per erroneous block, more than K bits per
erroneous block, and decoder-exception placeholders. Accept zero errors,
one-per-error-block, K-per-error-block, valid intermediate counts, and zero-
trial failed/incomplete records with null rates.
