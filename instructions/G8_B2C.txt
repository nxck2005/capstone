## Purpose

B2C is a narrow, pre-execution corrective checkpoint. B2's sharding direction
and closed unit-state schema are correct and are retained. A line-by-line audit
of the B2 primitives found that they do not yet supply the guarantees B3 exact
resume and merge validation will depend on:

1. **First publication is not crash-atomic.** `create_unit_state_exclusive`
   opened the *final* pathname with `O_CREAT | O_EXCL` and wrote into it. The
   exclusivity is real, but a hard exit between `open` and `fsync` leaves a
   truncated or partial JSON file at the authoritative name. A later reader
   cannot distinguish "never written" from "half written".
2. **Replacement was not linearizable.** `replace_unit_state` read the current
   state, compared its SHA-256 with `expected_previous_sha256`, and only then
   wrote a temporary and called `os.replace()`, with nothing held across that
   window. Two writers holding the same predecessor SHA could both pass the
   comparison and both report success; the second silently destroyed the
   first. That is a read-then-write, not a compare-and-swap, and the B2
   contract described it as one.
3. **Descriptors could be closed twice.** The failure path closed the raw
   descriptor inside `except` and again inside `finally`, so a genuine
   publication failure could surface to the caller as a secondary `EBADF`
   instead of the intended domain error.
4. **Symlink checks were fail-open.** `path.exists() and path.is_symlink()`
   follows the link, so a *dangling* symlink at the final state name, the root,
   the bucket directory, or a staging name reported `exists() == False` and
   passed the guard. Validation also compared two `resolve()` calls derived
   from the same candidate, which cannot prove anything an attacker-controlled
   parent has not already decided.
5. **Directory durability was silently downgraded.** `_fsync_directory`
   swallowed `EACCES` — which is a permission failure, not "unsupported" — and
   returned `False`; every caller discarded that return and reported success.
6. **Results were not request-bound and not terminal.** A `result_linked`
   state could carry a null `request_sha256`; and once linked, its result path,
   result SHA-256, trials, or attempt could still be rewritten by any writer
   holding the current SHA. Trials could decrease, a non-null request SHA could
   change, and the scientific flag could go true → false.
7. **Unit states did not bind their own contract.** Identity bound the B1C
   tooling contract only, so a state written under the superseded B2 contract
   was indistinguishable from one written under B2C.
8. **The independent verifier was not independent.** It imported every expected
   constant, field list, and status rule from `baseline.g8_bler_work_units`,
   so a mutation of the production module mutated the "expected" values in
   lockstep and the verifier still passed.
9. **A permanent no-live-state assertion was scheduled to fail.** The B2
   verifier and `test_b2_never_creates_live_work_unit_tree` asserted that
   `results/baseline/g8/work_units/` never exists. That is correct now and
   guaranteed to be wrong the moment B3/B4 legitimately execute.

B2C corrects all nine. No scientific result exists, no scientific parameter,
hypothesis, gate, operating rule or selection rule changes, and therefore **no
specification amendment is required**. B2 remains a historical implementation
checkpoint; B2C is the corrective checkpoint that must be green before B3.

## Adversary model

The corrected contract states its boundary explicitly rather than implying a
stronger one. B2C assumes a **trusted local user and a single trusted
repository checkout**. What it defends against is *accident and concurrency*:
two cooperating workers racing, a hard process kill mid-write, a stale writer
resuming with an obsolete predecessor SHA, an orphaned staging file, and a
symlink or alias that a careless tool or a partially-restored backup left
behind. It does **not** claim to defeat a local attacker who already has write
access to the work-unit root and can win an arbitrary time-of-check /
time-of-use race against a `renameat2`-less filesystem; the publication path is
descriptor-relative specifically to *narrow* that window, not to close it
against an unbounded adversary.
