## The two defects

**Defect 1 — the fixed-modulation curve searches instead of referencing.** BR-9
(`spec/concerns/baseline.md`) states that `params.baseline.core_modulation` *defines* the
fixed-modulation reference curve. The `CLASSICAL_FIXED_MOD` branch of `resolve_curve()` in
`src/baseline/classical/composition.py` instead enumerates every modulation present in the supplied
grid, sums each one's per-SNR best expected accuracies, and keeps whichever total is highest. That
makes the "fixed" arm a second optimizer rather than a reference, and it can report a BPSK or
16-QAM curve under the `classical_fixed_mod` label. The configured value is `qpsk`
(`params.baseline.core_modulation`) and it is characterized by the committed G-2 evidence, so the
configured value is live and reachable. This is a conformance defect against an existing normative
requirement, not a change to one.

**Defect 2 — resumed campaign state is trusted rather than validated.** `run_pass()` enforces
sequence position, non-blank scorer, scorer uniqueness across passes, `Selection` typing and
exhaustion. `_admit_resumed()` enforces only four things: `PassResult` type, known pass identifier,
no duplicate identifier, matching mode. A crash-resumed campaign can therefore be handed pass two
with no pass one, a reversed sequence, a gap, a blank or duplicated scorer, or a `PassResult` whose
`selections` hold objects that are not `Selection`s — and the state machine accepts all of it. This
is exactly the interruption path the resumable design exists to survive.

## C3.1 — correct fixed-modulation semantics

Correct `resolve_curve(CLASSICAL_FIXED_MOD, ...)` so that it:

1. reads `baseline.core_modulation` through the normal configuration interface — **never**
   hard-code `qpsk` in source;
2. verifies that the configured value is declared in `baseline.modulations`;
3. filters every SNR cell to candidates using exactly that modulation;
4. allows the LDPC rate and source encode axis to continue adapting per SNR;
5. never optimizes which modulation to hold fixed;
6. records the configured modulation in `CurveSelection.held_fixed`, with its source;
7. fails explicitly where a required cell cannot be constructed at all.

Never silently substitute another modulation when the configured one is absent or ineligible.

### The three cases, which are genuinely different

1. **The configured modulation is not declared in `params.baseline.modulations`.** A configuration
   contradiction. Raise `CompositionError`.
2. **No candidate using the configured modulation exists at a required SNR.** An incomplete
   campaign/candidate-grid construction defect. Raise a *distinct* `CompositionError` naming both
   the SNR and the configured modulation.
3. **Candidates using the configured modulation exist, but all of them are infeasible or
   uncharacterized.** **Do not raise, and do not substitute.** Preserve the `Selection` that
   `select_best()` returns — `selected = None`, `reason = no_eligible_candidate`, `evaluations` =
   all configured-modulation evaluations at that SNR.

Case 3 is deliberate. Structural infeasibility, codec infeasibility and missing BLER
characterization must remain **auditable** rather than either terminating the resolve or vanishing
from the curve. G-8's completeness preflight is what must later refuse to accept an uncharacterized
cell into a final adjudication; PB_3C's resolver preserves the cell and its reason so that preflight
has something to refuse.

Also update stale source comments and docstrings — in particular remove any wording that describes
`CLASSICAL_FIXED_MOD` as "chosen for the grid as a whole". It is the configured
`baseline.core_modulation` reference.

Required tests:

* the selected fixed modulation equals `get("baseline.core_modulation")` at every SNR and in
  `held_fixed`;
* a synthetic grid where BPSK has the best whole-grid total still selects QPSK;
* a grid where 16-QAM has the best whole-grid total still selects QPSK;
* rate and encode axis can adapt while modulation remains fixed;
* the configured modulation being undeclared fails closed;
* the configured modulation being absent at one SNR fails closed, naming that SNR;
* the configured modulation present with only infeasible candidates returns a curve point with
  `selected is None`;
* the configured modulation present with only uncharacterized candidates returns a curve point with
  `selected is None`;
* the preserved point retains its evaluation counts and reason;
* no other modulation is substituted in any of these cases;
* valid QPSK cells still select normally;
* adaptive mode remains adaptive;
* fixed-MCS mode remains unchanged.

The existing test that merely asserts `len(chosen) == 1` is insufficient — the defective
implementation satisfies it — and must be strengthened.

## C3.2 — harden resumed selection state

Resumed state must enforce the same invariants `run_pass()` enforces, rather than trusting stored
`PassResult` objects.

**Derive the permitted order from the configuration, not from arithmetic.** Do not implement resume
validation with hard-coded assumptions such as `expected = len(completed) + 1`. Take

    allowed = selection_passes()

and require the supplied resumed state to be an **exact ordered prefix** of `allowed`: for each
supplied result at index `i`, `result.pass_id == allowed[i]`. Therefore `()` is valid,
`(allowed[0],)` is valid, the complete allowed sequence is valid, and every other sequence is
invalid. Validate in the order supplied; never sort malformed state into validity.

Resumed-state admission must reject:

* pass two without pass one;
* a pass sequence beginning anywhere except pass one;
* gaps in the sequence;
* reversed pass order;
* duplicate pass identifiers;
* unknown pass identifiers;
* wrong mode;
* blank scorer names;
* reuse of the same scorer across pass one and pass two;
* non-`Selection` objects inside a stored `PassResult`;
* more completed passes than the configured limit;
* resumed state that claims a third pass.

Use **one shared validation helper** for the non-blank scorer, scorer uniqueness, `Selection`
typing, matching mode and permitted pass identifier. Both fresh execution and resumed admission
must call that helper, so the two paths cannot drift apart.

Ensure that:

* valid pass-one state may resume and execute exactly pass two;
* valid complete state is exhausted;
* pass-one results remain immutable;
* a resumed context cannot expose future state;
* scorer uniqueness applies identically to fresh and resumed execution.

Add explicit tests for every case above, plus a test proving that a future change to the configured
pass sequence is respected rather than silently assuming passes always begin at 1 and end at 2.

## C3.3 — freeze the selection tie-break before G-8

The existing order is

    expected_accuracy_descending
    success_probability_descending
    modulation_bits_per_symbol_ascending
    ldpc_rate_ascending
    encode_axis_px_descending
    candidate_id_ascending

**Do not change that order.** The issue is not the chosen order; it is that the order must be frozen
*before* the full validation table is inspected. Exact equality remains the tie definition — do not
introduce a tolerance parameter.

Prefer extending the existing generated adjudication over creating redundant hand-written truth.
The minimum acceptable implementation is that the W4 integration adjudication records the exact
ordered list, records that the order was frozen before G-8, and that the verifier compares the
recorded order against the implementation so a mutation to either fails verification.

**Recording the order and comparing it to the live module is necessary but not sufficient**, because
implementation and generator could in principle be changed together after sweep data exists. Add a
stable machine-readable **selection-policy fingerprint** — `selection_policy_sha256` — derived from
canonical, deterministic serialization of at least:

    tie_break_order
    tie_equality
    fixed_modulation.source
    fixed_modulation.configured_value
    selection_passes
    selection_termination_pass

with a canonical field order. The generator computes it; the verifier **independently recomputes**
it; a mutation of any covered policy field fails; and the adjudication states it was frozen before
G-8.

The corrected G-8 handoff must require the future campaign-opening manifest to bind the W4
integration adjudication file SHA-256, the `selection_policy_sha256`, and the PB_3C green commit or
resolved source identities — and must state that the future G-8 runner refuses to resume or
adjudicate if those bindings differ. PB_3C does not implement the G-8 campaign manifest; it records
this as a mandatory G-8 preflight requirement. That is what makes the preregistration
machine-enforceable rather than merely historically visible.

### Amendment judgment

Do **not** amend the specification solely because an implementation tie-break is now frozen. Add an
amendment only if conformance to an existing normative requirement is impossible without changing
that requirement. Record the judgment explicitly in `RESUME.md` and the worklog.

## C3.4 — correct the G-8 handoff

Update `NEXT.md`, `instructions/RESUME.md`, `AGENTS.md`, `README.md` and

The next task after PB_3C is *not* merely "construct `G8Authorization` and call
`select_operating_points()`". The current G-2 BLER artifact characterizes only a narrow conformance
identity and narrow SNR support. It is not the full BR-4 characterization table.

The handoff must say that G-8 begins by implementing and preflighting the campaign:

1. enumerate the complete **structural candidate/configuration grid** and the code-block identity
   grid;
2. identify every required `(rate, SNR, block identity, modulation)` characterization;
3. run and archive **full-strength BR-4 physical-layer BLER characterization** at the configured
   trial count;
4. build a separate hash-bound G-8 `BlerTable` artifact and loader;
5. verify complete coverage before selection;
6. generate cached codec reconstructions and measured clean-classifier accuracies on validation;
7. construct measured codec-accuracy objects from verified artifacts rather than arbitrary manual
   counts;
8. execute pass one;
9. build the training-only artifact corpus;
10. fine-tune the artifact classifier;
11. execute pass two once;
12. adjudicate the operating ratios and the other G-8 outputs.

Two terminology rules, and they are not cosmetic. **"Structural candidate/configuration grid"**,
not "feasible candidate grid": codec feasibility is not known until the codec-search artifacts are
produced, whereas structural transport identities can be enumerated first. **"BR-4 physical-layer
BLER characterization"**, not "validation BLER characterization": BLER characterization is a channel
simulation artifact, not a machine-learning validation-split measurement. Reserve "validation" for
codec/classifier selection records derived from the validation split.

The handoff must also state explicitly:

> G-8 selects the parameter named `crossover_ratio` using ER-3's learned-blind classical rule. It
> does not decide whether a learned-versus-classical curve crossover actually exists; that decision
> remains at G-10 after learned models exist.

The G-8 outputs named in the handoff must explicitly include: `efficiency_ratio`;
`crossover_ratio`; `low_ratio_operating_point`; classical non-degeneracy; the one-ratio versus
two-ratio full-strength ER-1 decision; the artifact-finetuned classifier release; the final pass-two
classical selections; and the frozen H2 validation window.

The handoff must preserve these facts: the G-2 table remains valid for G-2; it must not be
extrapolated or generalized; PB_3C does not build or execute the G-8 characterization; no real G-8
authorization exists yet; no sweep has started; no ratios have been selected; no classifier has been

    the authorized sweep.
